# 도그푸딩 교훈

이 저장소는 Orca 오케스트레이션(코디네이터 한 명과 워커 여러 명)으로 만들고 있다. 이 오케스트레이터가 하려는 일, 곧 티켓을 에이전트에 맡기고 질문에 답하고 결과를 받는 일을 사람이 직접 겪은 셈이다. 운영자 요청(2026-11-18)으로 그 과정에서 배운 점을 기록하고, 제품에 적용할 것은 반영 위치를 붙인다.

살아 있는 문서다. 새 교훈은 이후 문서 작업 때 이 파일 끝에 번호를 이어 덧붙이고, 후보가 ADR·스펙·티켓에 반영되면 반영 위치를 고친다.

## 형식

교훈마다 세 칸을 둔다.

- **관찰**: 코디네이터가 기록한 사실. 지어내지 않고 기록에 있는 것만 쓴다.
- **제품에 주는 뜻**: 이 오케스트레이터가 같은 일을 겪지 않게 하려면 무엇이 필요한가.
- **반영 위치**: 이미 반영했으면 그 ADR·스펙·티켓 링크, 아직 없으면 **후보**와 관련 티켓.

1~16의 관찰은 2026-11-17~18의 것이다.

## 1. 권한 승인 화면에서 워커가 멈춘다

**관찰.** 워커가 권한 승인 화면에서 자주 멈췄다. 대부분 PR 본문 갱신과 `rm -rf $변수/...` 정리를 한 줄로 묶은 명령이었다. 코디네이터는 원격에서 승인할 수 없어 "명령을 나눠 다시 하라"는 메시지를 보내 풀었다.

**제품에 주는 뜻.** 런의 에이전트도 권한 프롬프트에서 멈추고, 오케스트레이터는 ssh로 허용할 수 없다. 운영자에게 권한 대기를 보이고 어디서 허용하는지 알려야 하며, 대기 자체를 줄이려면 프로젝트의 에이전트 설정에서 필요한 권한을 미리 허용해 두는 편이 낫다.

**반영 위치.** 반영. 권한 대기 표시와 "러너 화면에서 허용해 주세요" 안내는 [ADR 0009](../adr/0009-run-via-orca-orchestration.md)와 [1단계 스펙](../spec/0001-phase-1.md) 3절 5번, 미리 허용 권장은 온보딩 [0026](../tickets/0026-web-onboarding.md)에 있다.

## 2. 입력 기다림 경보가 훅 실행 중에도 온다

**관찰.** "사람의 입력을 기다린다" 경보가 훅이 도는 중에도 와서 오탐이 잦았다. 코디네이터가 그때마다 터미널 출력을 읽어 실제로 기다리는지 확인해야 했다.

**제품에 주는 뜻.** 러너가 알리는 입력 기다림을 그대로 운영자에게 올리면 손댈 일에 거짓 항목이 쌓인다. 권한 대기·입력 기다림을 손댈 일에 올리기 전에 상태를 한 번 더 확인하는 단계가 필요하다.

**반영 위치.** 후보. 런 감시 [0016](../tickets/0016-worker-run-watch.md)과 관련된다.

## 3. 선행 작업을 기다리는 워커가 멈춤 경보를 보낸다

**관찰.** 선행 티켓을 기다리는 워커가 "보고 없이 멈춤" 경보를 반복해서 보냈다. 코디네이터는 이것을 이상 종료와 구분할 수 없었다.

**제품에 주는 뜻.** 일부러 기다리는 에이전트와 사라진 에이전트가 같은 신호로 보이면 운영자는 둘 다 확인해야 한다. "선행 작업 기다림"을 비정상 종료와 다른 상태로 보여야 한다.

**반영 위치.** 후보.

## 4. 끝난 워커에 보낸 메시지가 전달 실패로 경보된다

**관찰.** 워커가 끝난 뒤 그 워커에게 보낸 메시지가 전달되지 않았다는 경보가 왔다(`terminal_not_writable`). 메시지 내용은 이미 필요 없었다.

**제품에 주는 뜻.** 끝난 런에 대한 늦은 메시지나 답은 운영자가 할 일이 아니다. 조용히 버리거나 기록만 남기고 손댈 일에 올리지 않는다.

**반영 위치.** 후보.

## 5. 처리 안 된 완료 보고를 늦게 알았다

**관찰.** 완료 보고 하나가 "처리 안 됨"으로 남아 코디네이터가 늦게 알았다.

**제품에 주는 뜻.** Orca가 깨워 주는 것에만 기대면 놓친 보고를 알 수 없다. 메일을 소비하지 않고 읽고, 처리했는지는 오케스트레이터 DB를 기준으로 대조한다.

**반영 위치.** 반영. `check --peek`·`inbox`로 읽고 DB를 기준으로 삼는 결정은 [ADR 0009](../adr/0009-run-via-orca-orchestration.md)와 [1단계 스펙](../spec/0001-phase-1.md) 3절 5번(메일 읽기)에 있다.

## 6. 문서에 근거 없는 결정을 코디네이터가 대신 답했다

**관찰.** 워커가 물은 결정 가운데 문서에 근거가 없는 것을 코디네이터가 대신 답했고(Q62~Q65), 운영자가 그중 일부를 뒤집었다(Q66~Q68).

**제품에 주는 뜻.** 에이전트의 질문은 "문서로 답할 수 있는 것"과 "사람이 정할 것"으로 나뉜다. 사람이 정할 것은 반드시 운영자에게 가야 한다. 이 오케스트레이터는 에이전트 질문을 운영자에게 보이고 운영자가 답하게 한다.

**반영 위치.** 일부 반영. 질문 답하기 화면은 홈 [0020](../tickets/0020-web-home.md)과 Run 상세 [0022](../tickets/0022-web-run-detail.md)에 있다. 질문을 두 갈래로 나누는 일 자체는 아직 없다.

## 7. 번호와 추천을 붙인 결정 묶음은 빨리 답해진다

**관찰.** 결정을 번호와 추천을 붙인 묶음으로 물었을 때 운영자가 휴대폰에서 빠르게 답했다("ㅇㅇ").

**제품에 주는 뜻.** 질문 화면에 추천 답을 함께 보이고 "추천대로" 한 번에 답하기를 두면 운영자의 답이 빨라진다.

**반영 위치.** 후보. 질문 답하기 화면인 [0020](../tickets/0020-web-home.md)·[0022](../tickets/0022-web-run-detail.md)와 관련된다.

## 8. Door와 Blast radius로 병합 주체를 나눴다

**관찰.** PR 본문의 Door(one-way, two-way)와 Blast radius로 누가 병합할지 나눴다. 첫 one-way이고 blast radius가 큰 PR(#36)은 운영자가 승인해 병합했다.

**제품에 주는 뜻.** 지금 규칙은 사람 확인이 필요 없고 CI가 통과하면 에이전트가 직접 병합한다. 되돌리기 어렵고 닿는 곳이 큰 변경은 사람이 병합하도록 Door·Blast radius 기준을 더할지 정할 수 있다.

**반영 위치.** 후보. [ADR 0004](../adr/0004-agent-merges-its-own-pr.md)에 기준을 더할지 검토한다. 이 저장소의 규칙은 AGENTS.md 작업 흐름에 있다.

## 9. 병렬 워커 둘이 같은 DB 표를 만들 뻔했다

**관찰.** 병렬로 돌던 워커 둘이 같은 DB 표와 마이그레이션을 만들 뻔했다. 코디네이터가 소유자(0020)를 정하고 병합 순서를 정해 풀었다.

**제품에 주는 뜻.** 같은 파일이나 공유 자원을 건드릴 티켓을 동시에 할당하면 충돌이 난다. 그런 할당을 경고하거나 막는 기능이 필요할 수 있다.

**반영 위치.** 후보, 1단계 이후.

## 10. 대화로 정한 결정이 문서에 늦게 옮겨졌다

**관찰.** 대화에서 정한 결정이 문서에 늦게 옮겨지면 워커가 그 결정을 보지 못했다. 코디네이터는 결정 묶음마다 문서 워커를 따로 돌렸다.

**제품에 주는 뜻.** 운영자가 화면에서 답한 결정이 그 런의 답으로만 남으면 다음 런의 에이전트는 모른다. 답한 결정을 티켓이나 문서에 남기는 경로가 필요하다.

**반영 위치.** 후보.

## 11. 새 워크트리마다 setup이 필요했다

**관찰.** 새 워크트리마다 Node 버전 맞추기와 `pnpm install`(커밋 훅이 쓴다)이 필요했다. Orca 저장소 설정의 setup 스크립트로 풀었다.

**제품에 주는 뜻.** 러너 쪽 프로젝트에 setup이 준비되지 않으면 런마다 에이전트가 같은 준비를 하거나 커밋에서 막힌다. 러너 확인에서 setup 준비를 점검할 수 있다.

**반영 위치.** 후보. 러너 상태 확인 [0013](../tickets/0013-runner-orca.md)과 온보딩 [0026](../tickets/0026-web-onboarding.md)과 관련된다.

## 12. 비대화형 ssh에서 러너의 GitHub 인증이 동작하지 않았다

**관찰.** 러너의 GitHub 인증이 비대화형 ssh 세션에서 동작하지 않았다(macOS 키체인 잠김). `gh auth login --insecure-storage`와 `gh auth setup-git`으로 풀었다.

**제품에 주는 뜻.** 에이전트가 러너에서 push·PR을 하지 못하면 PR 상태를 정할 수 없다. 러너 필수 조건으로 점검하고 해결 방법을 안내해야 한다.

**반영 위치.** 반영. 러너 필수 조건과 `git push --dry-run` 점검은 [1단계 스펙](../spec/0001-phase-1.md) 9절, 안내는 온보딩 [0026](../tickets/0026-web-onboarding.md)에 있다.

## 13. 구현 전 외부 계약 검증이 큰 재작업을 막았다

**관찰.** 구현 전에 외부 계약을 실제로 돌려 본 검증이 두 사실을 먼저 찾았다. Orca는 에이전트 종료 코드를 주지 않고([research 0004](0004-orca-run-contract.md) 3절), 대화형 에이전트는 일을 마쳐도 끝나지 않는다. 이것이 큰 재작업을 막았다.

**제품에 주는 뜻.** 제품 개발 원칙이다. 외부 서비스에 기대는 계약은 구현 전에 실제 환경에서 돌려 보고, 결과를 research와 core 인터페이스에 먼저 반영한다.

**반영 위치.** 반영. 검증 티켓 0009~0012와 그 결과를 모은 [0037](../tickets/0037-core-adapter-contracts.md)의 흐름, [ADR 0009](../adr/0009-run-via-orca-orchestration.md)에 있다.

## 14. 계약을 크게 바꾸는 티켓은 독립 리뷰가 길어졌다

**관찰.** 계약을 크게 바꾸는 티켓 [0037](../tickets/0037-core-adapter-contracts.md)은 독립 리뷰를 일곱 번 돌았다.

**제품에 주는 뜻.** 개발 원칙이다. 계약 변경 티켓은 더 작게 쪼개 리뷰 한 번에 볼 범위를 줄인다.

**반영 위치.** 후보, 개발 원칙.

## 15. 셸 문자열로 조립한 지시문에서 결정이 빠졌다

**관찰.** 코디네이터가 워커 지시문을 셸 문자열로 조립하다 따옴표 때문에 결정 내용이 빠졌다.

**제품에 주는 뜻.** 에이전트에게 넘기는 프롬프트는 문자열을 이어 붙이지 않고 구조화해서 만들고, 빠진 부분이 없는지 검사한다. ssh로 보내는 명령을 인자 배열로 만들고 한 곳에서 이스케이프한다는 [CODING_STANDARDS](../../CODING_STANDARDS.md)의 규칙과 같은 원칙이다.

**반영 위치.** 후보. 러너 어댑터 [0013](../tickets/0013-runner-orca.md)과 관련된다.

## 16. 단순하고 위계가 분명한 시안이 채택됐다

**관찰.** 디자인 탐색에서 정보가 많은 시안과 규칙 기반 생성기는 거절되고, 단순하고 위계가 분명한 시안이 채택됐다. 운영자는 화면을 휴대폰에서 스크린샷 페이지로 확인했다.

**제품에 주는 뜻.** 제품 원칙이다. 화면은 무엇을 먼저 볼지 분명해야 한다.

**반영 위치.** 반영. [ADR 0007](../adr/0007-ui-list-detail-panel.md)의 화면 구조와 기각한 안에 있다.
