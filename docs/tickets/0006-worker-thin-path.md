# worker 얇은 경로: 대기열에서 결과 기록까지

## 목표

가짜 어댑터로 할당 → Queued → Running → Ended(두 축 기록)까지 한 번에 도는 worker 데몬 뼈대를 만든다. 이후 worker 티켓은 이 루프에 살을 붙인다.

## 범위

- 이 티켓은 `apps/worker`만 고친다.
- 폴링 루프: core의 엄격한 FIFO 규칙으로 Queued 런을 꺼낸다. 맨 앞 런이 정한 러너에 남은 capacity가 없으면 뒤 런도 시작하지 않는다(Q63 개정). 러너 없는 Queued 런은 순서에서 빠지고, 정한 러너가 Offline이 된 Queued 런은 러너를 비우며, 정한 러너에서 런의 러너 쪽 프로젝트가 사라진 Queued 런도 러너를 비운다(Q78). 맞는 Online 러너가 있거나 생기면 core 규칙으로 러너를 정해 원래 자리로 돌려놓는다(Q65·Q68·Q72·Q73). Running 런을 폴링해 에이전트 종료를 감지하고(종료 코드로 정상 종료·오류 종료), CodeHost로 PR을 찾아 core로 PR 상태를 정해 두 축을 기록한다(Q66). 요약 결과는 저장하지 않는다.
- 어댑터는 주입받는다. 어댑터와 DB 경로를 받아 worker 루프를 띄우는 함수를 내보낸다(0008이 가짜 어댑터로 띄울 때 쓴다). 이 티켓은 core의 가짜 어댑터로만 돈다.
- 러너의 Online 상태와 러너 쪽 프로젝트 목록은 0016 전까지 테스트가 DB에 직접 넣는다.
- 재시작 안전: 상태는 DB에만 두고, 데몬이 어느 지점에서 죽었다 다시 떠도 같은 런을 두 번 시작하지 않고 이어서 폴링한다(ADR 0002·0005).
- 런은 db의 할당 진입점(0005)으로 만든다.

## 완료 조건

- 가짜 어댑터로 런 셋을 할당하면 capacity만큼 시작하고 나머지는 Queued로 남았다가 차례로 시작한다는 테스트가 통과한다.
- 가짜 PR 상태(병합됨, 열림, 닫힘, 없음)와 종료 코드에 따라 두 축이 기록되고, core 요약 계산으로 Merged / Human Check / Failed가 나온다는 테스트가 통과한다.
- 맨 앞 런의 러너가 꽉 차 있으면 다른 러너의 뒤 런도 시작하지 않고, 러너 없는 Queued 런은 뒤 런을 막지 않는다는 테스트가 통과한다(Q63 개정·Q68).
- 런 시작 직후 데몬을 멈췄다 다시 띄워도 런이 하나만 시작된다는 테스트가 통과한다.
