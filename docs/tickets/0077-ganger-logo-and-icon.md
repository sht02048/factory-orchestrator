# 0077 Ganger 로고와 앱 아이콘

## 목표

운영자가 고른 브랜딩(2026-11-18)대로 기호·앱 아이콘·파비콘·워드마크·마스코트 원본을 만들고 화면과 문서에 넣는다.

## 배경

시안 네 차례를 거쳐 운영자가 정했다. 1·2차(일러스트형, 광택 있는 단일 도형)와 3차(흑백 방향 다섯)는 거절했고, 로고 유형 조사(워드마크·레터마크·그림 마크·추상 마크·마스코트·엠블럼·조합 마크와 호평 사례) 뒤 4차에서 **그림 마크(호루라기)와 마스코트(반장)를 둘 다** 쓰기로 했다. 평이 좋은 로고의 공통점(한 가지 기하 규칙으로 끝까지 줄이기, 디테일 하나, 작은 크기용 판을 따로 설계)을 따른다.

## 브랜드

- **두 기호의 역할**
  - 호루라기(기호): 앱 아이콘, 파비콘, 레일 맨 위, 워드마크 옆. 작은 자리와 "이 제품"을 가리키는 곳.
  - 반장(얼굴, 마스코트): README 머리, 온보딩, 빈 상태·로딩·오류 화면. 앱 아이콘·파비콘에는 쓰지 않는다.
- **호루라기**: 원 하나(몸통)와 둥근 사각 하나(입에 무는 곳)로 그리고, 몸통 가운데 구멍 하나를 뚫는다. 디테일은 노란 취구 하나뿐이다. 노란 바탕 위에서는 한 색으로만 그린다.
- **반장**: 흰 둥근 몸과 노란 챙 모자 하나. 표정은 눈 두 개로만 바꾼다. 표정 넷: 기본(윙크, README·온보딩), 신호 주는 중(호루라기를 문다, 런 맡기기·로딩), 쉬는 중(눈 감음과 z, 빈 상태), 걱정(눈썹, 러너 문제·404). 팔다리·옷을 더하지 않는다.
- **색**: Ink `oklch(0.14 0 0)`, Paper `oklch(0.97 0.003 85)`, Ganger Yellow `oklch(0.84 0.15 75)`. Ganger Yellow는 로고 그림(호루라기 취구)과 마스코트 그림(모자 챙) 안에서만 쓰는 **그림 색**이다. 앱 화면에서 노랑은 Human Check 상태 색(ADR 0010 5번)이므로 화면 크롬·버튼·면에는 쓰지 않는다. 앱 화면 안에 들어가는 기호(레일 맨 위)는 노랑 없는 한 색판을 쓴다. 마스코트는 그림이라 앱 화면(빈 상태 등)에서도 노란 모자를 유지하되, 상태를 나타내는 자리 곁에 두지 않는다.
- **워드마크**: `ganger`, Manrope ExtraBold, 소문자, 자간 −4%(OFL). 앱 화면 글자는 그대로 Pretendard다.
- **조합**: 가로판(기호 + 워드마크), 세로판, 레일 맨 위(기호 한 색판, Workspace 바꾸기는 그 아래 줄로 옮긴다). 기호 주위 여백은 취구 한 칸, 최소 크기는 기호만 16px(전용판), 조합 높이 20px.

## 범위

- **0080이 색 규칙을 대체한다.** 0080(앱 화면 브랜드 색)에서 Ganger Yellow가 강조색이 되므로, 이 티켓은 Ganger Yellow를 `packages/ui`의 브랜드 토큰 하나로만 두고 ADR 0010 5번 예외는 짧게 적는다. 브랜드 토큰을 기호·마스코트 밖에서 쓰면 실패하는 새 검사는 만들지 않는다.
- **ADR 0010 갱신**: 11번(레일 맨 위에 Workspace 바꾸기)을 "레일 맨 위에 제품 기호, 그 아래 Workspace 바꾸기"로 고치고, 5번(색 하나에 뜻 하나)에 브랜드 그림 색 예외(Ganger Yellow는 로고·마스코트 그림 안에서만, 화면 크롬·상태 표시에는 쓰지 않음)를 더한다. `packages/ui/src/tokens.test.ts`의 채도 있는 토큰 허용 목록과 `scripts/check-color-literals.ts`가 이 예외를 받도록 브랜드 그림 토큰(예: `brand.yellow`)을 `packages/ui`에 두고 시험을 고친다. 마스코트·기호 컴포넌트만 이 토큰을 쓴다.
- **원본 SVG**: 기호, 기호 한 색판, 파비콘 전용판(16·32px용으로 몸통을 키우고 구멍을 크게), 워드마크, 가로·세로 조합, 마스코트 표정 넷. 저장소에 원본을 둔다(위치는 `packages/ui` 또는 `assets/brand/` 중 저장소 관례로 정한다).
- **macOS 앱 아이콘** (조사 결과, macOS 26 기준)
  - 원본은 모서리 없는 1024 정사각형, 배경 레이어 하나 + 기호 레이어(몸통, 취구). 빛·그림자·그라데이션을 넣지 않는다(시스템이 Liquid Glass로 입힌다).
  - Icon Composer로 `.icon`을 만들고, macOS 15 이하용 `.icns`(iconutil, 16~512@2x 10장, squircle 모양을 그려 넣은 판)를 함께 둔다.
  - `@electron/packager` v18.4 이상에서 `icon`에 `.icns`와 `.icon`을 둘 다 넘긴다. `.icon` 컴파일은 macOS 26·Xcode 26 이상이 필요하다(서명 맥북에서 릴리스할 때 확인, 0031).
  - dmg 볼륨 아이콘에 쓸 `.icns`를 준비한다. dmg를 만들고 볼륨 아이콘을 넣는 일은 0031(릴리스)이 한다.
  - Xcode 26이 없는 기기에서도 `pnpm --filter desktop package`가 깨지지 않게, `.icon`을 컴파일할 수 없으면 `.icns`만 넣는다. `.icns`와 `.icon`을 함께 넘기는 packager 동작은 구현 때 문서와 실제 빌드로 확인한다(저장소는 `@electron/packager` 20.x).
  - 트레이 아이콘(`apps/desktop/assets/trayTemplate*.png`)을 호루라기 템플릿 이미지(검정 한 색, 투명 바탕)로 바꾼다.
- **웹**: `favicon.ico`(16·32를 손으로 다듬은 전용판), `icon.svg`(prefers-color-scheme 대응), `apple-touch-icon.png`(180, 불투명). 레일 맨 위 로고와 Workspace 바꾸기 위치 조정.
- **마스코트를 화면에**: 빈 상태(Dashboard·Tickets 등), 404, 연결 끊김 화면, 온보딩 첫 화면, 앱 첫 로딩 화면에만 둔다. 목록·상태 알약·버튼 옆과 러너 문제 카드 안에는 두지 않는다. 표정과 자리: 기본(온보딩), 신호 주는 중(첫 로딩), 쉬는 중(빈 상태), 걱정(404·연결 끊김). 마스코트 컴포넌트는 `packages/ui`에 두고 `/ds` 미리보기를 붙인다.
- **README는 고치지 않는다.** README 머리(반장 + 워드마크 + 한 줄 소개)는 제목을 Ganger로 바꾸는 0078이 이 티켓의 원본을 써서 넣는다. 이 티켓은 화면에 보이는 제품 이름도 바꾸지 않는다(0078).
- 워드마크 SVG는 글자를 아웃라인(패스)으로 바꿔 글꼴 파일 없이 보이게 하고, Manrope(OFL) 고지를 원본 폴더에 둔다.

## 완료 조건

- 아이콘이 `pnpm dev` 화면(파비콘, 레일)과 패키징한 앱(.app)에 보인다는 스크린숏을 PR에 붙인다. macOS 26 이상과 macOS 15 이하에서의 앱 아이콘 확인은 워커가 쓸 수 있는 기기로 하고, 확인하지 못한 판은 PR에 적어 0031(서명 맥북)에서 확인한다.
- 브랜드 그림 토큰 예외가 시험·색 검사를 통과하고, 그 토큰을 기호·마스코트 밖에서 쓰면 실패한다는 시험.
- 16px 파비콘이 밝은·어두운 브라우저 탭에서 알아볼 수 있다는 스크린숏.
- 마스코트가 빈 상태·404에 보이고 화면 읽기에는 장식으로 숨겨진다는 시험.
