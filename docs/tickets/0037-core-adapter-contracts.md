# core 어댑터 인터페이스를 검증 결과에 맞추기

## 목표

검증 티켓(0009~0012)의 결과로 `Tracker`·`Runner`·`CodeHost` 인터페이스와 가짜 어댑터를 한 번에 고친다. 어댑터 티켓(0013~0015)이 `packages/core`를 고치지 않고 함께 돌 수 있게 하려는 것이다.

## 범위

- 이 티켓은 `packages/core`와, 인터페이스가 바뀌면 그것을 부르는 `apps/worker`·`apps/web`·`e2e/` 코드(core 열거값에 새 값이 생기면 그 값의 화면 메시지 포함), 검증 결과로 런에 새로 저장할 값이 생기거나 core 타입이 바뀌면(Q77·Q82의 에이전트 결과와 Ended 런, 아래 오케스트레이션 값) 그것을 따르는 `packages/db` 스키마·코드·마이그레이션(0005의 Ended 런 제약 포함)과, Q77의 런 취소 요청과 Q82.3의 질문 답 요청을 남기고 읽는 `packages/db` 테이블·마이그레이션·접근 함수만 고친다. 0006·0008 뒤, 0016 앞에 둬서 그동안 `apps/worker`를 고치는 다른 티켓이 없게 한다.
- 0009~0012 research 문서에 맞춰 인터페이스 타입, 외부 열거값, 오류 종류를 고친다(에이전트 멈추기 방법, 입력 기다림 신호, webhook 이벤트 분류, 티켓 키로 PR 찾기 등).
- 고친 뒤에도 core가 ADR [0008](../adr/0008-pluggable-tracker-runner-codehost.md)을 따르는지 확인한다. 0004가 만든 종류별 ID와 등록(`ids.ts`, `registry.ts`)을 유지하고, research 0002 「어댑터 인터페이스 초안」의 서비스 전용 이름(`orcaPath`, `linearIssue` 등)을 core에 다시 들이지 않는다. ADR 0008은 이 초안보다 우선한다.
- 운영자 결정 Q82 개정(런 실행 방식, ADR [0009](../adr/0009-run-via-orca-orchestration.md), 스펙 3절 4~6번): 런은 대화형 에이전트를 러너의 Orca 오케스트레이션으로 맡겨 돌린다. research [0008](../research/0008-orca-orchestration-run.md) 「제안: Runner 어댑터 계약」을 출발점으로 `Runner` 인터페이스와 가짜 어댑터를 고친다. 서비스 이름(`Task`, `Dispatch`, `worker_done`, `dispatchId` 등)은 core에 들이지 않고 불투명한 ID와 core 낱말(완료 보고, 질문, 우편함 터미널)로 둔다(ADR 0008).
  - 질문과 답: 진행 폴링이 에이전트 질문(본문, 선택지, 불투명한 메일 ID)과 권한 대기를 구분해 돌려주고, 질문에 답하기와 권한 거절을 인터페이스에 더한다. 허용은 없다(Q82.3·Q82.4).
  - 완료 보고: 진행 폴링이 완료 보고(outcome 성공·실패, 보고 본문)와 보고 없이 사라짐을 돌려주고, 완료 보고를 받은 뒤 에이전트를 닫는 동작을 더한다(Q82.2·Q82.19).
  - 우편함: 러너마다 우편함 터미널 핸들과 오케스트레이션 Run을 두고, 어댑터가 만들고 사라지면 다시 만든다. 메일은 소비하지 않고 읽고, 처리한 메일 ID는 db에 둔다(Q82.1·Q82.5·Q82.7).
  - 실제 브랜치 저장: 시작 결과가 러너에서 받은 실제 브랜치 이름을 돌려주고 db 런 레코드에 저장한다. PR 찾기 1순위는 이 이름이다(Q82.6).
- 에이전트 결과를 스펙 4.2대로 아홉으로 바꾼다: 정상 종료·오류 종료를 완료 보고(성공)·완료 보고(실패)로 바꾸고, 비정상 종료와 시작할 수 없음을 더한다(Q82.2·Q82.16·Q82.19·Q82.20). 요약 결과에 Canceled를 더하고, 요약 계산 함수를 스펙 4.2 표대로 고친다. 운영자가 취소함으로 끝난 런에 러너에 닿지 못한 채 끝났는지를 저장하고 요약 계산 함수의 입력으로 쓴다(Q82.18·Q82.21).
- 운영자 결정 Q77·Q82.8~Q82.12(런 취소): 런 상태 전이에 Ended가 아닌 모든 상태 → Ended(취소)를 더한다. Queued에서 취소해 끝난 런은 러너·워크트리·시작 시각이 없고 PR 상태가 없음으로 고정되니 Ended 런 타입이 이를 받게 한다. 취소 중(처리되지 않은 취소 요청이 있는 런)은 런 상태가 아니라 db의 요청으로 안다. 운영자가 취소한 티켓을 자동 할당 조건에서 빼고, 취소 뒤 라벨이 다시 붙으면 다시 할당 대상이 되게 한다. 리드 타임 계산은 시작하지 않고 끝난 런의 대기 시간을 할당부터 끝낸 시각까지, 실행 시간을 0으로 센다(Q82.9·Q82.20).
- 운영자 결정 Q82.13·Q82.14·Q82.16·Q82.22(대기열): 러너 고르기에서 GitHub 인증이 깨진 러너를 빼고, 그 러너로 정한 Queued 런을 Q78 런처럼 러너를 비워 순서에서 뺀다. 순서에서 빠진 런의 이유(Offline, 러너에서 프로젝트가 빠짐, GitHub 인증 깨짐)를 구분해 돌려준다. 맨 앞 런이 영영 시작할 수 없으면(예: Mapping 삭제) 시작할 수 없음으로 끝낸다.
- 운영자 결정 Q79: CI 상태는 선택 표시다. `CiState`에 "권한이 없어 볼 수 없음"을 "CI 없음"과 구분해 더한다. CI 상태는 요약 결과에 쓰지 않는다.
- 운영자 결정 Q78: 엄격한 FIFO 대기열에서, 정한 러너에 그 런의 러너 쪽 프로젝트가 없어진 Queued 런을 Offline 예외와 같이 다룬다(러너를 비우고 순서에서 빼고, 맞는 러너가 생기면 원래 자리로).
- 시작 멱등: 오케스트레이터가 시작 전에 정하는 결정적 워크트리 이름(`--name`)을 시작 전에 DB에 쓰고 멱등 키로 쓴다. 브랜치는 Orca가 접두사를 붙여 정하므로 멱등 키로 쓰지 않는다(Q82.6). 러너가 응답한 뒤 Running을 쓰기 전에 데몬이 죽었으면, 재시작 때 러너 어댑터가 그 이름으로 이미 시작한 런을 찾아 이어 붙인다(Orca는 `name:` 선택자, research 0003·0004·0008). 0006 worker는 지금 이 경우에 시작을 새로 보낸다.
- 가짜 어댑터를 같은 인터페이스에 맞춘다. 바뀐 점은 PR에 적는다.
- 검증 결과로 고칠 것이 없으면 그 근거를 PR에 적는다. 운영자 결정 Q77~Q79와 Q82 개정(Q82.1~Q82.22)의 반영은 이 문장으로 건너뛸 수 없다.

## 완료 조건

- core·worker·web·e2e의 기존 테스트와 저장소 전체 typecheck가 통과한다.
- 에이전트 결과 아홉 × PR 상태 넷(시작할 수 없음은 없음만)과 운영자가 취소함의 러너에 닿지 못함 여부의 모든 조합이 스펙 4.2 표대로 요약 결과와 워크트리 처리를 돌려준다는 테스트가 통과한다(Q77·Q82). 완료 보고(실패) + 열림이 Human Check이고, 운영자가 취소함이 PR 상태와 상관없이 Canceled라는 경우를 따로 확인한다.
- Queued·Running·Waiting for Input·Disconnected 런의 취소는 받아들이고 Ended 런의 취소는 거부한다는 테스트가 통과한다(Q82.8).
- 운영자가 취소한 티켓은 라벨이 남아 있어도 할당 조건에 맞지 않고, 취소 뒤 라벨이 다시 붙으면 맞는다는 테스트가 통과한다(Q82.12).
- GitHub 인증이 깨진 러너를 고르지 않고, 그 러너로 정한 Queued 런이 러너를 비우고 순서에서 빠진다는 테스트와, 맨 앞 런이 영영 시작할 수 없으면 시작할 수 없음으로 끝나 뒤 런이 막히지 않는다는 테스트가 통과한다(Q82.14·Q82.16·Q82.22).
- 가짜 러너 어댑터로 질문 → 답하기, 권한 대기 → 거절, 완료 보고(성공·실패), 보고 없이 사라짐을 재현할 수 있다.
- 정한 러너에서 러너 쪽 프로젝트가 사라진 Queued 런이 러너를 비우고 순서에서 빠졌다가, 맞는 러너가 생기면 원래 자리로 돌아온다는 테스트가 통과한다(Q78).
- CI 상태 "볼 수 없음"이 요약 결과를 바꾸지 않는다는 테스트가 통과한다(Q79).
- 런 취소 요청과 질문 답 요청을 db에 남기고 한 번만 꺼내 처리 표시를 할 수 있고, Queued에서 취소해 러너·워크트리·시작 시각 없이 PR 상태 없음으로 끝난 런을 저장할 수 있다는 db 테스트가 통과한다(Q77·Q82.10).
- 0009~0012에서 확인한 사실 중 인터페이스에 닿는 것마다 반영 여부가 PR에 적혀 있다.
