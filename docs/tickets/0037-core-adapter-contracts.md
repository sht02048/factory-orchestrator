# core 어댑터 인터페이스를 검증 결과에 맞추기

## 목표

검증 티켓(0009~0012)의 결과로 `Tracker`·`Runner`·`CodeHost` 인터페이스와 가짜 어댑터를 한 번에 고친다. 어댑터 티켓(0013~0015)이 `packages/core`를 고치지 않고 함께 돌 수 있게 하려는 것이다.

## 범위

- 이 티켓은 `packages/core`와, 인터페이스가 바뀌면 그것을 부르는 `apps/worker`·`apps/web`·`e2e/` 코드(core 열거값에 새 값이 생기면 그 값의 화면 메시지 포함), 검증 결과로 런에 새로 저장할 값이 생기거나 core 타입이 바뀌면(Q77의 에이전트 결과와 Ended 런) 그것을 따르는 `packages/db` 스키마·코드·마이그레이션(0005의 Ended 런 제약 포함)과, Q77의 런 취소 요청을 남기고 읽는 `packages/db` 테이블·마이그레이션·접근 함수만 고친다. 0006·0008 뒤, 0016 앞에 둬서 그동안 `apps/worker`를 고치는 다른 티켓이 없게 한다.
- 0009~0012 research 문서에 맞춰 인터페이스 타입, 외부 열거값, 오류 종류를 고친다(에이전트 멈추기 방법, 종료 코드, 입력 기다림 신호, webhook 이벤트 분류, 티켓 키로 PR 찾기 등).
- 고친 뒤에도 core가 ADR [0008](../adr/0008-pluggable-tracker-runner-codehost.md)을 따르는지 확인한다. 0004가 만든 종류별 ID와 등록(`ids.ts`, `registry.ts`)을 유지하고, research 0002 「어댑터 인터페이스 초안」의 서비스 전용 이름(`orcaPath`, `linearIssue` 등)을 core에 다시 들이지 않는다. ADR 0008은 이 초안보다 우선한다.
- 운영자 결정 Q77(런 취소): 에이전트 결과에 "운영자가 취소함"을 더하고, 요약 계산 함수에 스펙 4.2의 두 줄(열림 → 남김, 그 밖 → 바로 지움, 둘 다 Failed)을 더하고, 런 상태 전이에 Queued·Running → Ended(취소)를 더한다. 취소는 Queued·Running 런에만 허용한다는 규칙을 core에 둔다(상태 전이 표만으로는 Waiting for Input → Ended도 허용된다). Queued에서 취소해 끝난 런은 러너·워크트리·시작 시각이 없을 수 있으니 Ended 런 타입이 이를 받게 한다. 이런 런의 PR 상태, 대기 시간, 통계 포함 여부는 스펙 11절 열린 질문 2·4의 답을 따르고, 답이 나오기 전에는 그 부분을 구현하지 않는다(티켓 README 「운영자 답 대기」).
- 운영자 결정 Q79: CI 상태는 선택 표시다. `CiState`에 "권한이 없어 볼 수 없음"을 "CI 없음"과 구분해 더한다. CI 상태는 요약 결과에 쓰지 않는다.
- 운영자 결정 Q78: 엄격한 FIFO 대기열에서, 정한 러너에 그 런의 러너 쪽 프로젝트가 없어진 Queued 런을 Offline 예외와 같이 다룬다(러너를 비우고 순서에서 빼고, 맞는 러너가 생기면 원래 자리로).
- 가짜 어댑터를 같은 인터페이스에 맞춘다. 바뀐 점은 PR에 적는다.
- 검증 결과로 고칠 것이 없으면 그 근거를 PR에 적는다. 운영자 결정 Q77~Q79의 반영은 이 문장으로 건너뛸 수 없다.

## 완료 조건

- core·worker·web·e2e의 기존 테스트와 저장소 전체 typecheck가 통과한다.
- 에이전트 결과 일곱 × PR 상태 넷의 모든 조합이 스펙 4.2 표대로 요약 결과와 워크트리 처리를 돌려준다는 테스트가 통과한다(Q77).
- Queued·Running 런의 취소는 받아들이고, Waiting for Input·Disconnected·Ended 런의 취소는 거부한다는 테스트가 통과한다(Q77, 스펙 11절 질문 1의 답이 나오면 그에 맞춘다).
- 정한 러너에서 러너 쪽 프로젝트가 사라진 Queued 런이 러너를 비우고 순서에서 빠졌다가, 맞는 러너가 생기면 원래 자리로 돌아온다는 테스트가 통과한다(Q78).
- CI 상태 "볼 수 없음"이 요약 결과를 바꾸지 않는다는 테스트가 통과한다(Q79).
- 런 취소 요청을 db에 남기고 한 번만 꺼내 처리 표시를 할 수 있다는 db 테스트가 통과한다. Queued에서 취소해 러너·워크트리·시작 시각 없이 끝난 런을 저장할 수 있다(Q77).
- 0009~0012에서 확인한 사실 중 인터페이스에 닿는 것마다 반영 여부가 PR에 적혀 있다.
