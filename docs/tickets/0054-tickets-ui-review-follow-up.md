# 0054 Tickets UI 리뷰 후속

## 목표

수동 할당 뒤 포커스와 결과를 잃지 않게 하고, 티켓이 많아도 목록이 무겁지 않으며 잘린 사실을 알 수 있게 한다.

## 배경

UI 리뷰 판정은 Approve with changes였다.

## 범위

### 고칠 것(Should fix)

1. **할당 뒤 포커스.** 라우트(`routes/_app/tickets.tsx`)의 `onAssign`이 `router.invalidate()`를 기다린 뒤 돌아오고, 그다음에야 `assign-dialog.tsx`가 `setOpen(false)`를 부른다. 다시 읽은 데이터에서 그 티켓은 할당할 수 없게 되어 대화상자가 열린 채 언마운트되고 트리거도 사라진다. `unassigned` 필터면 행이 목록에서 빠져 패널이 다른 티켓으로 바뀐다. 성공하면 먼저 닫고 그다음 다시 읽는다. 다시 그린 패널의 "런 보기"나 선택 행으로 포커스를 옮긴다. `unassigned` 필터에서 할당한 티켓의 선택을 남길지 정한다.
2. **할당 중 닫기.** `onOpenChange`가 보내는 중에도 닫기를 막지 않는다. 닫은 뒤 실패하면 알 길이 없다. 보내는 중에는 닫지 않거나, 닫힌 뒤 실패하면 토스트로 알린다.
3. **목록 규모.** `load.ts`가 트래커 프로젝트마다 250 × 4쪽, 최대 1000개를 읽고 모두 그린다. 프로젝트가 여럿이면 N×1000행이다. 목록을 가상화하고(고정 행 높이 `size.rowMinHeight`), 필터 탭 개수는 한 번만 센다.
4. **잘림 안내.** `MAX_PAGES`에 닿아도 다음 쪽 커서를 버리고 표시를 남기지 않는다. 잘린 트래커 프로젝트를 페이지 값에 담아 목록 위에 "{project}는 최근 1000개만 보여요" 같은 줄을 보인다.

### 하면 좋은 것(Nits)

- 불러오기 오류 묶음이 `role="alert"`라 화면에 들어올 때마다 읽힌다. `role="status"`나 일반 영역으로 둔다.
- `messages/ko/tickets.json`의 `subtitle`이 두 문장이다(ADR 0010 8번 한 줄 요약).
- `target="_blank"` 링크에 새 탭 표시가 없다.

## 범위 밖

- 트래커에서 1000개보다 많이 읽는 일(서버 쪽 검색·페이지 나누기)은 따로 정한다.

## 완료 조건

- 할당이 성공하면 대화상자가 닫히고 포커스가 `body`가 아니라는 브라우저 시험.
- 보내는 중에는 대화상자가 닫히지 않는다는(또는 닫힌 뒤 실패를 토스트로 알린다는) 시험.
- 1000행 목록에서 그려진 행 DOM 수가 화면에 보이는 수 근처라는 시험.
- 잘린 트래커 프로젝트 안내가 보인다는 시험.
