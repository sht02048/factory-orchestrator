# worker 런 감시: 입력 기다림, 완료 보고, 시간 초과, 연결 끊김, 취소

## 목표

런이 도는 동안 생기는 예외 상황을 스펙대로 처리한다.

## 범위

- 이 티켓은 `apps/worker`만 고친다. 어댑터는 계속 core의 가짜 어댑터로 시험한다.
- 입력 기다림: 폴링 결과가 질문이나 권한 대기면 런을 Waiting for Input으로, 다시 움직이면 Running으로 바꾼다. 시간 초과 시계는 멈추지 않는다(Q52·Q82.3). 질문은 내용과 선택지를 DB에 쓰고, web이 DB에 남긴 답을 러너 어댑터로 보낸 뒤 답했음을 기록한다. 답은 한 번만 보낸다. 권한 대기는 그 사실만 DB에 쓴다(허용은 러너 화면에서 사람이 한다). 메일을 처리했는지는 DB가 기준이다(Q82.5).
- 완료 보고: 폴링 결과가 완료 보고면 outcome으로 에이전트 결과(완료 보고 성공·실패)를 정하고 PR 상태를 함께 기록한 뒤 에이전트를 닫는다(Q82.2). 보고 없이 사라졌으면 에이전트 결과 비정상 종료로 끝낸다(Q82.19). 워크트리 처리는 요약 계산 함수가 정한다(뒤처리는 0017).
- 시간 초과: Workspace의 최대 실행 시간(기본 2시간)을 넘기면 에이전트를 멈추고 끝낸다. 에이전트 결과는 Running이었으면 시간 초과, Waiting for Input이었으면 입력 기다리다 멈춤이고, PR 상태를 함께 기록한다(Q39·Q70). 워크트리 처리는 따로 정하지 않고 요약 계산 함수로 계산한다(Q51, CODING_STANDARDS 「요약 결과는 계산 함수 하나로만 정한다」).
- 연결 끊김: 런 중 ssh가 5분 동안 계속 실패하면 런을 끝내지 않고 Disconnected로 바꾼다. 워크트리는 건드리지 않는다. 5분 안에 다시 닿으면 상태를 바꾸지 않고 이어서 본다(Q50·Q67).
- 다시 연결: Disconnected 런의 러너에 다시 닿으면 실제 상태를 확인한다. 에이전트가 돌고 있으면 Running으로, 입력을 기다리고 있으면 Waiting for Input으로 돌아가고, 이미 끝났으면 보통 종료처럼 두 축을 기록하고(뒤처리는 0017), 워크트리가 사라졌으면 에이전트 결과 워크트리 없음으로 끝낸다(Q67). Running·Waiting for Input 중 워크트리가 사라져도 워크트리 없음이다(Q49).
- 돌아오지 않음: Disconnected인 채 최대 실행 시간이 지나면 에이전트 결과 러너 연결 끊김으로 끝내고 PR 상태를 기록한다. 워크트리는 자동으로 지우지 않는다(Q67·Q75).
- 취소: web이 DB에 남긴 취소 요청을 처리한다(스펙 3절 6번, Q77·Q82.8~Q82.11). 에이전트 결과는 운영자가 취소함이다. Queued 런은 바로 끝내고 PR 상태를 없음으로 둔다(PR을 찾지 않는다). Running·Waiting for Input 런은 에이전트를 멈춘 뒤 끝내고 PR 상태를 함께 기록한다. 멈추기가 실패하면 요청을 처리하지 않은 채 두고(화면의 취소 중) 다음 폴링에 다시 시도한다. Disconnected 런(취소 중에 Disconnected가 된 런 포함)은 다시 연결되면 멈추고 끝내고, 다시 닿지 않은 채 최대 실행 시간이 지나면 러너에 닿지 못한 채 끝났다고 기록하고 운영자가 취소함으로 끝낸다(러너 연결 끊김이 아니다, Q82.21). 이미 Ended인 런의 요청은 처리하지 않는다. 요청은 한 번만 처리한다. 워크트리 처리는 요약 계산 함수가 정한다(뒤처리는 0017).
- 러너 상태 확인을 주기적으로 돌려 Online/Offline, 확인 시각, 그 러너가 가진 러너 쪽 프로젝트 목록, 프로젝트별 GitHub 인증 결과(`git push --dry-run`, Q82.15)를 DB에 쓴다(Runners 화면, Settings Mapping, 러너 고르기가 쓴다). 인증이 깨진 러너는 할당에서 빠지고 손댈 일에 오르며, 그 러너로 정한 Queued 런은 러너를 비운다(Q82.14·Q82.22, core 규칙은 0037).
- 시작할 수 없음: 대기열 맨 앞 런이 영영 시작할 수 없으면(예: Mapping 삭제) 시작할 수 없음으로 끝낸다(Q82.16, core 규칙은 0037).
- 재시작 안전: 5분 시계와 시간 초과 시계는 DB의 시각으로 계산해 재시작 뒤에도 이어진다. Disconnected 런도 재시작 뒤 다시 연결 확인을 이어 간다.

## 완료 조건

- 가짜 시계와 가짜 어댑터로 각 상황(입력 기다림 왕복, 입력 기다림 중 시간 초과 → 입력 기다리다 멈춤, PR 열린 시간 초과, ssh 4분 실패 뒤 회복, ssh 5분 실패 → Disconnected, 다시 연결 뒤 에이전트 돌고 있음 → Running, 다시 연결 뒤 입력 기다림 → Waiting for Input, 다시 연결 뒤 에이전트 끝남 → 두 축 기록, 다시 연결 뒤 워크트리 사라짐 → 워크트리 없음, Disconnected인 채 최대 실행 시간 지남 → 러너 연결 끊김, Running 중 워크트리 사라짐, PR 열린 Running 취소, Queued 취소 → PR 상태 없음, Waiting for Input 취소, 멈추기 실패 뒤 다시 시도, Disconnected 취소 뒤 다시 연결 → 운영자가 취소함, Disconnected 취소 뒤 최대 실행 시간 지남 → 러너에 닿지 못한 채 운영자가 취소함, 질문 → 답 보내기 → Running, 권한 대기 → Waiting for Input, 완료 보고 성공·실패 → 에이전트 닫기, 보고 없이 사라짐 → 비정상 종료)이 테스트로 통과한다.
- 같은 질문의 답이 데몬을 다시 띄워도 한 번만 보내진다는 테스트가 통과한다.
- 러너 확인 결과에서 정한 러너의 러너 쪽 프로젝트가 사라진 Queued 런이 러너를 비우고 순서에서 빠진다는 테스트가 통과한다(Q78, core 규칙은 0037).
- Disconnected 동안 워크트리를 지우거나 에이전트를 멈추는 러너 호출이 없다는 테스트가 통과한다.
- ssh 실패 도중 데몬을 다시 띄워도 5분 시계가 처음부터 다시 시작하지 않는다는 테스트가 통과한다.
