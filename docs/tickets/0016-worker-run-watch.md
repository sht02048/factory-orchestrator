# worker 런 감시: 입력 기다림, 시간 초과, 러너 연결 끊김

## 목표

런이 도는 동안 생기는 예외 상황을 스펙대로 처리한다.

## 범위

- 이 티켓은 `apps/worker`만 고친다. 어댑터는 계속 core의 가짜 어댑터로 시험한다.
- 입력 기다림: 폴링 결과가 입력 기다림이면 런을 Waiting for Input으로, 다시 움직이면 Running으로 바꾼다. 시간 초과 시계는 멈추지 않는다(Q52).
- 시간 초과: Workspace의 최대 실행 시간(기본 2시간)을 넘기면 에이전트를 멈추고 Failed(시간 초과)로 끝낸다(Q39). 워크트리를 남길지는 판정 함수가 돌려준 값을 그대로 기록한다(Q51, CODING_STANDARDS 「런 결과는 판정 함수 하나로만 정한다」).
- 러너 연결 끊김: 런 중 ssh가 5분 동안 계속 실패하면 런을 끝내고, 결과는 판정 함수로 Failed(러너 연결 끊김)를 정한다. 5분 안에 다시 닿으면 이어서 본다(Q50). 워크트리가 사라져도 러너 연결 끊김이다(Q49).
- 러너 상태 확인을 주기적으로 돌려 Online/Offline, 확인 시각, 그 러너가 가진 러너 쪽 프로젝트 목록을 DB에 쓴다(Runners 화면, Settings Mapping, 러너 고르기가 쓴다).
- 재시작 안전: 5분 시계와 시간 초과 시계는 DB의 시각으로 계산해 재시작 뒤에도 이어진다.

## 완료 조건

- 가짜 시계와 가짜 어댑터로 각 상황(입력 기다림 왕복, 입력 기다림 중 시간 초과, PR 열린 시간 초과, ssh 4분 실패 뒤 회복, ssh 5분 실패, 워크트리 사라짐)이 테스트로 통과한다.
- ssh 실패 도중 데몬을 다시 띄워도 5분 시계가 처음부터 다시 시작하지 않는다는 테스트가 통과한다.
