# web 홈 화면

## 목표

현재 Workspace에서 손댈 일, 실행 중, Queued를 한눈에 본다.

## 범위

- 이 티켓은 `apps/web`의 홈 라우트와 그 화면 메시지만 고친다. 앱 셸은 고치지 않는다(0007).
- 손댈 일: 요약 결과가 Human Check·Failed인 런(Canceled 런은 넣지 않는다, Q82.9), Waiting for Input·Disconnected("연결 끊김") 런과 이유 한 줄(Q52·Q67), GitHub 인증이 깨져 할당에서 빠진 러너와 해결 안내(Q82.14·Q82.15). 취소를 요청했지만 아직 끝나지 않은 런에는 "취소 중"을 함께 보인다(Q82.21).
- 질문 답하기: 질문으로 Waiting for Input인 런은 손댈 일에서 질문 내용과 답하기 칸(선택지가 있으면 선택지)을 보인다. 답하면 DB에 답을 남기고 worker가 보낸다. web은 ssh를 쓰지 않는다(Q61·Q82.3). 권한 대기인 런은 "러너 화면에서 허용해 주세요"를 안내하고 거절만 둔다.
- 손댈 일의 Ended 런은 에이전트 결과와 PR 상태 두 칸을 나란히 보인다(Q66). 요약 결과는 core 요약 계산 함수로 계산한다. 실행 중: Running. Queued: 엄격한 순서(들어온 순서)로 보이고, 순서에서 빠진 런은 "맞는 러너가 Offline이라 기다리는 중"을 함께 보인다(Q68). Q78로 러너를 비운 런은 "러너에서 프로젝트가 빠져 다시 고르는 중"을 보인다(Q82.13). GitHub 인증이 깨져 러너를 비운 런(Q82.22)의 문구는 스펙 11절 질문 11의 답을 따르고, 답 전에는 정하지 않는다.
- "전체" Workspace에서는 모든 Workspace의 손댈 일만 보인다(ADR 0006).
- 목록 + 오른쪽 상세 패널(ADR 0007, 시안 B).

## 완료 조건

- 테스트 DB의 런이 세 구역에 맞게 나뉘고, Queued가 들어온 순서로 보인다는 테스트가 통과한다.
- Waiting for Input 런이 손댈 일에 "입력 기다림"으로, Disconnected 런이 "연결 끊김"으로 보인다는 테스트가 통과한다.
- 손댈 일의 Ended 런에 에이전트 결과와 PR 상태가 따로 보인다(예: 완료 보고(실패) + 열림)는 테스트가 통과한다.
- Canceled 런이 손댈 일에 없다는 테스트가 통과한다.
- 질문으로 기다리는 런에서 답하면 DB에 답이 하나 생기고, 권한 대기 런에는 허용 없이 안내와 거절만 보인다는 테스트가 통과한다.
- "전체"에서 손댈 일만 보인다는 테스트가 통과한다.
