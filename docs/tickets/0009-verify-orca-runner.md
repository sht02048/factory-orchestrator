# 검증: Orca 러너 상태 확인과 정리 계약

## 목표

Runner 어댑터의 상태 확인·멈추기·정리 부분을 짓기 전에, 스펙 10절의 Orca 사실 중 러너 상태와 워크트리 정리에 걸린 것을 실제 러너에서 확인해 `docs/research/`에 남긴다.

## 범위

- 스펙 10절 1, 6, 7, 9, 19번:
  - 1: 런타임이 꺼졌을 때 `orca status --json`과 다른 명령의 `error.code`·종료 코드
  - 6: ssh 비대화형 셸에서 `orca`가 런타임에 닿는지
  - 7: Linux 러너의 `orca` 설치 경로와 `orca serve` 서비스 구성
  - 9: `worktree rm` 출력과 에이전트가 도는 워크트리를 지울 때의 동작
  - 19: 시간 초과 때 에이전트를 멈추는 명령(`worktree rm --force`로 갈음할지, 다른 명령이 있는지)
- 결과는 research 0002와 같은 형식(출처 표시 **[실행]**·**[문서]**)으로 `docs/research/0003-orca-runner-contract.md`에 쓴다. 실제 출력은 가상 값으로 바꿔 어댑터 테스트 픽스처로 쓸 수 있게 둔다.
- 운영자 준비가 필요하다: ssh로 닿는 테스트 러너(macOS 하나, 7번은 Linux 하나)와 버려도 되는 테스트 저장소. 운영자 환경 값은 문서에 넣지 않는다(ADR 0005).

- 함께 도는 검증 티켓끼리 번호가 겹치지 않게 research 번호는 0003으로 정해 둔다. 픽스처는 `docs/research/fixtures/0003/`에 둔다.

## 완료 조건

- 다섯 항목마다 확인한 사실과 근거(실행 출력 또는 문서 인용)가 research 문서에 있고, 확인하지 못한 항목은 이유와 함께 남아 있다.
- 19번의 답으로 Runner 어댑터의 "에이전트 멈추기"를 어떤 명령으로 할지 적혀 있다.
