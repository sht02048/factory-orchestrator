# Runner 어댑터: runner-orca

## 목표

core의 `Runner` 인터페이스를 ssh로 원격 `orca`를 실행해 구현한다.

## 범위

- 이 티켓은 새 패키지 `packages/runner-orca`만 만든다(Q56). `packages/core`는 고치지 않는다. 검증 결과에 따른 인터페이스 변경은 0037이 먼저 한다.
- ssh 실행: 러너 설정의 ssh 대상과 orca 실행 파일 경로를 쓴다. `--prompt` 등 인자는 원격 셸에 맞게 이스케이프한다(스펙 8절).
- `--json` 봉투(`ok`, `result`, `error.code`)를 경계에서 스키마로 파싱한다. 모르는 열거값은 열어 두고 모르는 런 상태는 Running으로 다룬다.
- 상태 확인(스펙 9절의 러너 필수 조건: Orca 상시 서비스 설치 여부와 비대화형 ssh 세션의 GitHub 인증, Q43), 러너 쪽 프로젝트 목록, 워크트리 만들기와 에이전트 시작(`--surface terminal`, `--retry-launch`), 진행 폴링(입력 기다림, 에이전트 종료 코드, 워크트리 사라짐), 에이전트 멈추기(0009 19번 결과), 로그 꼬리, 워크트리 지우기(브랜치는 남김).
- ssh 실패는 오류 종류로 돌려준다. 5분 판단은 worker와 core가 한다.

## 완료 조건

- 0009·0010의 실제 출력 픽스처(로그 꼬리와 러너 쪽 프로젝트 목록 포함)와, 모자란 경우 이 티켓이 테스트 러너에서 새로 받은 출력으로 각 메서드의 파싱 테스트가 통과한다(성공, `ok: false`, 깨진 출력).
- 줄바꿈·따옴표·`$`가 든 프롬프트가 이스케이프된 명령 문자열로 바뀌는 테스트가 통과한다.
- GitHub 인증 확인(0037이 상태 확인 결과에 더한 자리)이 성공과 실패를 구분한다는 테스트가 통과한다. 확인에 쓴 명령과 그 이유를 PR에 적었다.
- 테스트 러너에 직접 붙여 상태 확인과 러너 쪽 프로젝트 목록을 돌린 결과를 PR에 적었다(운영자 준비 필요, 0009와 같은 러너).
