# 0078 코드·패키지·문서 이름을 Ganger로 바꾸기

## 목표

0076에서 정한 새 이름으로 저장소 전체를 바꾼다.

## 배경

옛 이름이 저장소 추적 파일 241개에 있다(0076 배경). 거의 모든 파일을 고치므로, 다른 작업과 겹치지 않게 진행 중인 화면 개편과 0074(검사 강제)가 끝난 뒤에 한 번에 한다.

## 범위

- 패키지 이름(`@factory/*` → 0076의 새 범위)과 모든 import, pnpm 워크스페이스·Turborepo 설정, lockfile.
- CLI 명령, 설치·데이터 폴더, 환경 변수, 데스크톱 앱 번들 ID·이름. 이미 설치한 곳을 옮기는 코드는 만들지 않는다(아래 운영자 결정).
- 화면 문구·메시지 파일·문서 제목의 제품 이름, README·AGENTS.md·GLOSSARY·DESIGN.md. README 머리에는 0077의 원본(반장 + 워드마크)과 한 줄 소개를 넣는다.
- 지난 티켓·research 기록은 그 시점 기록이라 고치지 않는다.
- CI, smoke 시험, 서버 배포물(bundle) 스크립트의 이름.

## 완료 조건

- `git grep -iE "factory[- ]orchestrator|@factory/|FACTORY_"` 결과가 옛 이름이 남아도 되는 곳 말고는 없다. 남아도 되는 곳: 지난 기록(`docs/tickets`, `docs/research`)과 결정 기록(`docs/adr`)뿐이다.
- 전체 CI와 데스크톱 패키징이 통과한다.
- 머지 위험은 one-way(설치 폴더·환경 변수 이름 변경)라 사람이 직접 병합한다(AGENTS.md).
- PR 본문에 옛 이름으로 띄운 기계를 손으로 옮기는 방법을 적는다.

## 운영자 결정(2026-11-18)

공개 전이라 옛 이름으로 설치한 곳이 사실상 없다. 그래서 ADR 0011의 옮기기 규칙(폴더를 옮기고 링크 남기기, 옛 환경 변수를 경고와 함께 받기, 옛 서비스·userData·로그인 항목 정리)을 코드로 만들지 않는다. 코드는 새 이름만 쓰고 옛 `FACTORY_*`는 읽지 않는다. 옛 이름으로 띄운 개발 기계는 운영자가 PR 본문의 방법대로 손으로 옮긴다(ADR 0011 갱신).
