# 0095 러너 등록 간소화 1: 고르기 화면, Ganger 전용 ssh 키, 이 맥을 러너로

## 목표

러너 등록을 "어느 맥에서 돌릴지 고르기 → Ganger가 대신 준비하기"로 줄인다. 첫 단계로 고르기 화면, Ganger 전용 ssh 키와 호스트 키 고정, "이 맥을 러너로" 흐름을 만든다. 다른 맥 등록은 0097(명령)·0099(Ganger 앱)가 잇는다.

## 배경

운영자가 직접 러너를 등록하며 겪은 문제(2026-11-19): 원격 로그인 켜기, 서버 맥에서 키 만들기, ssh-copy-id, 호스트 지문 yes, which orca, 서비스 설치(안내의 `--refuse-public`은 없는 옵션이라 실패), gh 토큰을 파일로, git 도우미 바꾸기까지 열 단계 넘게 손으로 했다. 저장하면 폼이 위로 튀고, 확인 중 표시가 없었다. ssh 대상 예시가 옛 이름(factory@runner.example.com)이었다.

## 운영자 결정(2026-11-19, 시안 U10·U11·RL1·U12·U14)

- **고르기 화면.** 맨 위에 이 서버 맥의 상태(이름, Orca 설치·경로, 원격 로그인, Tailscale). 질문 "에이전트를 어느 맥에서 돌릴까요?" 줄 오른쪽에 범례 한 번("직접 해요" 노란 칸, "Ganger가 해요" 회색 칸). 선택지 셋(이 맥 / 다른 맥 · Ganger 앱 / 다른 맥 · 명령). 고른 카드 안에만 단계 칩 줄과 "약 1분". 칩은 화면 읽기용 이름("직접 해요: 원격 로그인 켜기")을 가진다. "직접 입력하기(ssh 설정을 이미 해 둔 경우)"는 접어 두고 지금 폼을 그 안에 둔다.
- **Ganger 전용 ssh 키와 호스트 키 고정.** 서버가 처음 켜질 때 `<home>/ssh/`에 ed25519 키(암호 없음, 0600)를 만든다. Ganger가 등록한 러너의 ssh 호출은 `-i <home>/ssh/id_ed25519 -o IdentitiesOnly=yes -o UserKnownHostsFile=<home>/ssh/known_hosts -o StrictHostKeyChecking=yes`를 쓴다. 직접 입력으로 등록한 러너와 이미 등록된 러너는 지금처럼 사용자의 ssh 설정을 쓴다.
- **이 맥을 러너로.** 원격 로그인이 꺼져 있으면 공유 설정 열기와 3단계 안내를 보이고 22번 포트가 열릴 때까지 기다린다. 켜지면 서버가 같은 사용자로 Ganger 공개 키 등록, localhost 호스트 키 고정, orca 경로 찾기, Orca 상시 서비스 설치, GitHub 인증 정리(gh가 로그인돼 있을 때만), 러너 등록(`<계정>@localhost`, 자리 1)을 하고 단계마다 결과를 체크 줄로 보인다.
- **확인 결과.** 저장·등록 뒤 화면이 위로 튀지 않고 결과가 아래에 나타나며 포커스는 결과 제목으로 간다. 확인 중에는 항목마다 진행 표시를 보인다.
- **작은 버그.** `--refuse-public`을 없애고 실제 Orca CLI 옵션과 맞는지 시험으로 지킨다. ssh 대상 예시를 새 이름으로 바꾼다.
- Runners 화면의 "러너 추가"도 같은 고르기 흐름을 쓴다.

## 범위

- `packages/runner-orca`: 러너 설정에 관리 방식(`access`)을 더하고, Ganger 관리 러너의 ssh 호출 옵션을 붙인다. 서비스 설치 명령을 한곳에서 만들고 hint에서 `--refuse-public`을 뺀다. push 확인 코드는 건드리지 않는다(0096).
- `packages/app`: Ganger ssh 키, 이 맥 상태 읽기, 이 맥 준비 단계.
- `apps/web`: 고르기·이 맥·결과 화면(온보딩 Runner 단계, Runners 러너 추가), 서버 함수, 메시지.
- `demo/`: `pnpm dev`에서 쓰는 가짜 "이 맥".
- 운영자 결정(2026-11-19, 시안 M2a·M2b): 고르기 화면의 "직접 입력하기" 접는 칸을 없애고, 계속 버튼 줄 오른쪽 "주소 직접 입력하기" 링크로 주소(`direct=true`)가 바뀌는 입력 전용 화면을 연다. 두 다른 맥 선택지는 흐리게 막고 제목 옆 "곧 지원" 꼬리표만 둔다. 온보딩과 Runners 러너 추가 모두 같다.

## 완료 조건

- 서비스 설치 명령의 옵션이 `orca serve service install --help` 픽스처에 있는 옵션인지 시험한다.
- ssh 호출 옵션 시험: Ganger 관리 러너는 키·known_hosts 옵션을 붙이고, 직접 입력 러너는 붙이지 않는다.
- 이 맥 준비 시험(임시 HOME): authorized_keys 권한 700/600과 중복 없음, known_hosts에 localhost 호스트 키, orca 경로 찾기, gh가 없을 때 경고만, 실패를 사람이 읽을 이유로, gh 토큰이 결과에 남지 않음.
- 화면 시험: 서버 맥 상태, 범례, 고른 카드의 칩과 화면 읽기용 이름, 직접 입력 접힘, 원격 로그인 기다림, 단계 체크 줄, 결과 제목 포커스.
- 스크린숏(1280px): 고르기(이 맥 선택), 이 맥(원격 로그인 기다림·진행 중·끝), 결과.
- M2 시험: 직접 입력 링크가 주소를 바꾸고 새로 고침·뒤로 가기에 맞게 움직이며, 바뀌면 포커스가 새 제목으로, 맥 고르기로 돌아오면 링크로 간다. 스크린숏 M2a·M2b(1280px, 400px).
- 마무리 리뷰: `better-interface`로 1728~400px, 그 뒤 `interface-review`. 두 표를 PR 본문에.
- 개발 맥에서 실제로 "이 맥을 러너로"를 끝까지 돌린다(원격 로그인이 켜져 있으면).

## 정한 것(구현 때)

- 두 "다른 맥" 선택지는 `disabled`로 흐리고 제목 옆에 "곧 지원" 꼬리표를 둔다(M2). 계속 버튼은 늘 보인다. 0097·0099가 이 자리를 연다.
- 직접 입력 화면(M2b)은 지금 러너 폼을 그대로 쓰되 ssh 대상을 맨 앞에 두고, 이름은 ssh 대상의 호스트 첫 부분으로 미리 채우며(사용자가 바꾸면 유지), orca 경로는 Orca 앱 기본 경로로 채운다. 비우면 자동으로 찾기는 0097로 넘겼다. 이 화면만 "확인하고 등록" 버튼과 `ssh -o BatchMode=yes <대상> true` 복사 명령을 보인다.
- 관리 방식은 러너 설정 JSON의 `access`(`{ kind: "ganger", identityFile, knownHostsFile }`)다. 없으면 직접 입력이다. DB 스키마는 바꾸지 않았지만 저장 형식이 늘어 one-way다.
- 확인 중에는 항목마다 진행 표시를 둔다.
- Runners의 "러너 추가"는 Settings로 가지 않고 Runners 패널(`/runners?sel=new`)에 같은 흐름을 연다. 헤더의 "러너 추가"가 주 버튼이라 패널 안 버튼은 모두 보조 버튼이다. "이 맥"으로 등록하면 흐름과 단계 결과를 남기고 포커스를 "러너 보기" 버튼으로 옮긴다. 직접 입력으로 추가하면 새 러너를 골라 그 행에 포커스를 옮기고 패널에 확인 결과를 보인다.
- 0096이 먼저 머지돼 결과 카드는 0096의 묶음 표기("GitHub push · 저장소 N개 모두 통과", 실패 저장소와 이유)를 그대로 쓴다.
- 공유 설정 열기 버튼은 이 맥에서 도는 데스크톱 앱(Electron, loopback 주소)에서만 보이고, 데스크톱 앱이 그 링크만 바깥으로 연다. 그 밖에는 "이 맥에서 시스템 설정 > 일반 > 공유를 열어요" 안내 문구를 보인다.
