# web 끝난 화면에 런 실행 결정 반영

## 목표

운영자 결정 Q82 개정(Q82.1~Q82.22)은 web 티켓 0007·0023·0024를 닫은 뒤에 나왔다. 그 화면들을 결정에 맞춘다.

## 범위

- 이 티켓은 `apps/web`의 Runs(0007), Runners(0023), Stats(0024) 라우트와 그 화면 메시지만 고친다. core 열거값과 요약 계산 함수는 0037이 바꾼다.
- Runs(0007): 요약 결과 필터에 Canceled("취소")를 더한다(Q82.18). Queued 이유에 "러너에서 프로젝트가 빠져 다시 고르는 중"(Q82.13)과 GitHub 인증이 깨져 러너를 비운 이유(Q82.22)를 더한다. 처리되지 않은 취소 요청이 있는 런에 "취소 중"을 보인다(Q82.21).
- Runners(0023): 러너 쪽 프로젝트별 GitHub 인증 결과(`git push --dry-run`)와, 깨졌을 때 할당에서 빠졌다는 표시와 해결 안내를 보인다(Q82.14·Q82.15). 러너에 닿지 못한 채 끝난 운영자가 취소함 런을 남은 워크트리 수에 넣는다(Q82.21).
- Stats(0024): 요약 결과 분포에 Canceled를 "취소"로 따로 세고 성공·실패율에서 뺀다. 시작하지 않고 끝난 런(Queued에서 취소, 시작할 수 없음)의 대기 시간은 할당부터 끝낸 시각까지, 실행 시간은 0이다(Q82.9·Q82.20). Failed의 두 축 조합에 새 에이전트 결과(완료 보고, 비정상 종료, 시작할 수 없음)가 보인다(Q82.2·Q82.16·Q82.19).

## 완료 조건

- Runs 필터로 Canceled 런만 볼 수 있고, Queued 이유 세 가지가 각각 다른 문구로 보인다는 테스트가 통과한다.
- Runners에서 GitHub 인증이 깨진 러너가 할당에서 빠졌다고 보이고, 러너에 닿지 못한 채 끝난 취소 런이 남은 워크트리 수에 든다는 테스트가 통과한다.
- Stats에서 Canceled 런이 성공·실패율에 들지 않고 따로 세어지며, 시작하지 않고 끝난 런의 실행 시간이 0이라는 테스트가 통과한다.
