# 리디자인 적용: UI 낱말과 시각 규칙

## 목표

운영자가 고른 시안 B(아이콘 레일 + 손댈 일 카드 + 오른쪽 실시간 흐름)와 [ADR 0010](../adr/0010-ui-words-and-visual-rules.md)의 규칙 11가지를 모든 화면에 적용한다. 같은 상태는 어느 화면에서나 같은 이름·모양·색으로 보이고, 시간 표기와 제목 규칙이 하나가 된다.

## 배경

운영자가 구현된 화면이 딱딱하다고 해 pen.dev로 시안을 다시 만들었고 B안을 골랐다(비교 페이지는 운영자 비공개 자료라 링크하지 않는다). 점검에서 깨진 규칙 16가지(낱말 혼용, 같은 것의 여러 이름, 상태 모양·색 불일치, 주 버튼 여러 개, 시간 표기 7종, 제목 규칙 3종, 메뉴의 Settings·Workspace 누락 등)를 찾았고, 운영자가 2026-11-18에 ADR 0010의 규칙으로 정했다(Q14~Q21). GLOSSARY는 같은 PR에서 상태 이름을 화면에서도 영어 용어로 쓰도록 바꿨다.

## 범위

### `packages/ui`

- **토큰.** 둥글기 카드 12·버튼·행·입력 8·알약 6. 색 의미 토큰: 보라(Question·Permission·Waiting for Input), 노랑(Human Check, 지금 주황 `check`를 바꾼다), 빨강(Failed·Disconnected·Runner Issue·Offline), 초록(Running·Online), 파랑(Merged), 회색(Queued·Canceled). 영역을 나누는 면(배경색) 토큰. `tokens.test.ts`의 "채도 있는 색은 포인트·Human Check·Failed·Online에만" 검사를 새 색 의미에 맞춘다. 색 검사(`check:colors`)는 그대로 통과해야 한다.
- **상태 알약 컴포넌트 하나.** "점 + 이름" 알약. 상태 값(런 상태, 요약 결과, 러너 Online·Offline, 손댈 일 종류)을 받아 색을 컴포넌트가 고른다. 지금의 `Status`·`Dot`(`tone`)을 이것으로 바꾸거나 합친다. 화면이 색을 직접 고르지 않게 한다.
- **버튼 위계.** 주 버튼(파랑, 화면에 하나), 보조 버튼, 위험 보조 버튼(빨간 글자). 질문 선택지는 모두 보조 버튼이다.
- **카드.** 손댈 일 카드·러너 카드에 쓰는 면 컴포넌트(둥글기 12).
- `DESIGN.md`를 ADR 0010에 맞게 고친다("카드와 배지를 쓰지 않는다", "색은 손댈 일에만", 반경 표). `/ds` 미리보기를 고친다.

### 화면

- **레일 셸.** 왼쪽 아이콘 레일. 맨 위 Workspace 바꾸기, 메뉴 Home·Tickets·Runs·Runners·Stats, 맨 아래 Settings. Runners 아이콘에 Runner Issue 개수 점.
- **Home.** 손댈 일 카드(종류 알약, 회색 키 + 제목, 설명 문장, 주 행동 하나) + 오른쪽 "지금 일어나는 일" 흐름. 흐름은 DB에 이미 있는 사건(런 상태 바뀜, 질문, 권한 대기, 런 끝·PR)만 쓰고, "커밋 n개" 같은 런 중간 진행은 넣지 않는다(데이터가 없다, ADR 0010).
- **Runs.** 상태 칩 필터 + 둥근 행. 목록 + 상세 패널은 그대로(ADR 0007).
- **Run 상세.** 전체 화면. 질문 카드를 맨 위에, 그 아래 타임라인(시각 "10:45"), 정보, 터미널 끝부분.
- **Runners.** 러너 카드(Online·Offline 알약, capacity 막대 "2/2", 문제가 있으면 해결 안내).
- **온보딩.** 왼쪽 단계 목록(Tracker·GitHub·Runner·Workspace·Mapping) · 가운데 입력 · 확인 결과. 단계는 모두 필수이고 확인이 성공해야 다음으로 간다(그대로).
- **Tickets·Stats·Settings.** 같은 규칙(상태 알약, 제목 + 요약 한 줄, 티켓 표기, 둥글기, 버튼 위계, 시간 표기)을 적용한다. 구조는 그대로다.
- **Runner Issue를 손댈 일에 올린다.** 지금 Home의 손댈 일에는 GitHub 인증이 깨진 러너만 오르고 Offline 러너는 오르지 않는다. Offline 러너도 Runner Issue로 올린다.

### 문구와 표기

- **메시지 파일 낱말 통일**(`apps/web/messages/ko/*.json`). 상태·종류·화면 이름을 영어 용어로: "실행 중" → Running, "입력 기다림" → Waiting for Input, "연결 끊김" → Disconnected, 요약 결과 "취소" → Canceled, "질문"·"권한 대기"(종류 이름) → Question·Permission, "인증 깨짐" → Runner Issue + 설명 문장, "홈" → Home. 설명 문장·버튼("취소" 버튼 포함)·"손댈 일"·"전체"·에이전트 결과·PR 상태 값은 한국어 그대로.
- **화면 제목.** 메뉴와 같은 화면 이름 + 그 아래 한 줄 요약 문장.
- **티켓 표기.** 어디서나 회색 키 + 제목.
- **시간 표기 함수 하나.** 경과("25분째"), 상대("방금"·"25분 전"·하루 넘으면 날짜), 시각("10:45")을 한 모듈에서 만든다. 시간대는 운영자 설정(`apps/web/src/time-zone.ts`, 티켓 0044)을 따른다. 화면이 시간을 따로 만들지 않는다.

## 하위 티켓 제안

한 PR로는 크다. 아래처럼 나누면 앞 하나 뒤에 화면 티켓을 함께 돌릴 수 있다. 나눌 때 이 티켓은 묶음 티켓으로 남긴다.

1. **0049a `packages/ui` 토큰·상태 알약·버튼·카드 + 시간 표기 함수 + 메시지 낱말 통일.** 다른 모든 하위 티켓의 선행.
2. **0049b 레일 셸 + Home**(손댈 일 카드, 지금 일어나는 일, Runner Issue).
3. **0049c Runs + Run 상세.**
4. **0049d Runners + 온보딩.**
5. **0049e Tickets·Stats·Settings 규칙 맞추기.**

2~5는 서로 다른 라우트를 고쳐 함께 돌 수 있다. 셸(2)과 겹치는 루트 레이아웃은 2가 맡는다.

## 완료 조건

- 화면에 상태 이름이 GLOSSARY 영어 용어로만 보인다는 시험이 통과한다. 메시지 파일의 상태·종류·화면 이름 값이 영어 용어 목록과 같다는 시험과, 각 화면의 상태 알약 글이 영어 용어 목록 안에 있다는 시험. 렌더 결과 전체를 낱말로 거르지 않는다(에이전트 결과 "러너 연결 끊김"처럼 한국어로 두는 설명 값이 있다).
- `apps/web`이 상태를 상태 알약 컴포넌트 하나로만 그린다는 시험이 통과한다(예: 앱 코드에 다른 상태 표시 컴포넌트 import가 없고, 상태 값마다 알약이 ADR 0010의 색을 고른다는 컴포넌트 시험).
- 시간 표기 함수 시험이 통과한다: 경과 "25분째", 1분 안 "방금", "25분 전", 하루 넘으면 날짜, 시각 "10:45", 운영자 시간대 반영.
- 화면마다 파란 주 버튼이 하나 이하라는 시험이 통과한다(Home 카드·Run 상세·Runners·온보딩).
- Offline 러너가 손댈 일에 Runner Issue로 오르고 Runners 아이콘 점 개수에 든다는 시험이 통과한다.
- `tokens.test.ts`가 새 색 의미와 둥글기 값을 검사하고, `check:colors`·브라우저 e2e·smoke가 그대로 통과한다.
- `pnpm dev`로 띄운 Home·Runs·Run 상세·Runners·온보딩·Tickets·Stats·Settings 스크린샷을 PR에 붙인다.
