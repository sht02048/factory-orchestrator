# worker 런 뒤처리와 web 요청 처리

## 목표

런이 시작하고 끝날 때 트래커·러너에 해야 할 일과, web이 DB에 남긴 요청을 처리한다.

## 범위

- 이 티켓은 `apps/worker`만 고친다.
- Linear 갱신: 런 시작 때 Workspace의 "In Progress" 상태로 바꾸고, 런이 끝나면 결과 댓글(요약 결과, 에이전트 결과, PR 상태, PR 링크)을 단다. Queued인 동안은 바꾸지 않는다(Q68). 그 밖에는 갱신하지 않는다(Q41·Q57, ADR 0001).
- 워크트리 정리: 런의 두 축으로 요약 계산 함수를 불러 돌려받은 워크트리 처리를 따른다(Q44·Q51, CODING_STANDARDS 「요약 결과는 계산 함수 하나로만 정한다」). 바로 지움이면 지우고 지운 시각을 기록한다. 워크트리 참조가 없는 런(Queued에서 취소한 런)은 지우기를 부르지 않고 지운 시각도 남기지 않는다(스펙 4.2). 브랜치는 지우지 않는다.
- 러너 연결 끊김 런과 러너에 닿지 못한 채 끝난 운영자가 취소함 런(Q82.21): 워크트리를 자동으로 지우지 않는다. 사람이 러너에서 지우면 러너 확인 때 워크트리가 사라진 것을 보고 지운 시각을 기록한다(Q75).
- PR을 남긴 런 이후: 요약 계산 함수의 워크트리 처리가 PR이 병합되거나 닫힐 때까지 남김인 런(Human Check, PR 열린 시간 초과·입력 기다리다 멈춤·비정상 종료·운영자가 취소함. Queued에서 취소한 런은 PR 상태가 늘 없음이라 들지 않는다, Q82.10)의 PR을 주기적으로 조회해 병합되거나 닫히면 이후 PR 상태로 런에 기록하고 워크트리를 지운다. 두 축은 바꾸지 않는다(Q51·Q54·Q69).
- PR·CI 상태: 런과 이어진 PR의 상태와 CI 상태를 폴링해 DB에 쓴다. Run 상세(0022)가 읽는다.
- 트래커 갱신은 DB의 갱신 기록을 보고 한 번만 한다. 재시작해도 결과 댓글이 두 번 달리지 않는다(ADR 0002·0005).
- 로그: 런이 끝날 때 마지막 200줄을 저장한다(Q46). 에이전트를 닫기 전에 읽는다. 보고 없이 사라진 런은 닫은 뒤 보관본이 비어 있을 수 있다(research 0008 6절).
- web 요청 처리: web이 DB에 남긴 로그 꼬리 요청과 러너 확인 요청을 ssh로 처리해 결과를 DB에 쓴다(Q61). 요청은 한 번만 처리한다.

## 완료 조건

- 가짜 어댑터로 런 시작·종료 때 트래커 호출이 각각 한 번씩(상태 변경, 댓글)만 일어나고, 댓글을 단 직후 데몬을 다시 띄워도 댓글이 하나라는 테스트가 통과한다.
- 러너 연결 끊김 런의 워크트리는 러너가 다시 Online이 돼도 worker가 지우지 않고, 가짜 러너에서 워크트리를 없애면 지운 시각이 기록된다는 테스트가 통과한다(Q75).
- 워크트리 처리 값별로 지우거나 남기고, 남긴 런의 PR이 병합·닫힘으로 바뀌면 이후 PR 상태를 기록하고 지우며 두 축은 그대로라는 테스트가 통과한다.
- DB에 넣은 로그 꼬리 요청·러너 확인 요청이 처리돼 결과가 써진다는 테스트가 통과한다.
