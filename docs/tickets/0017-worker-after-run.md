# worker 런 뒤처리와 web 요청 처리

## 목표

런이 시작하고 끝날 때 트래커·러너에 해야 할 일과, web이 DB에 남긴 요청을 처리한다.

## 범위

- 이 티켓은 `apps/worker`만 고친다.
- Linear 갱신: 런 시작 때 Workspace의 "In Progress" 상태로 바꾸고, 런이 끝나면 결과 댓글(결과, PR 링크, Failed 사유)을 단다. 그 밖에는 갱신하지 않는다(Q41·Q57, ADR 0001).
- 워크트리 정리: Merged·Failed는 끝나면 바로 지우고(러너 연결 끊김 런은 러너가 다시 Online이 되면 지운다, Q64), 남길지는 판정 함수가 돌려준 값을 따른다(Q44·Q51, CODING_STANDARDS 「런 결과는 판정 함수 하나로만 정한다」). 지운 시각을 기록하고, 브랜치는 지우지 않는다.
- Human Check 뒤: 남긴 런의 PR을 주기적으로 조회해 병합되거나 닫히면 그 PR 상태를 런에 기록하고 워크트리를 지운다. 결과는 바꾸지 않는다(Q54). PR 열린 시간 초과 런도 같은 때 워크트리를 지운다(Q51).
- PR·CI 상태: 런과 이어진 PR의 상태와 CI 상태를 폴링해 DB에 쓴다. Run 상세(0022)가 읽는다.
- 트래커 갱신은 DB의 갱신 기록을 보고 한 번만 한다. 재시작해도 결과 댓글이 두 번 달리지 않는다(ADR 0002·0005).
- 로그: 런이 끝날 때 마지막 200줄을 저장한다(Q46).
- web 요청 처리: web이 DB에 남긴 로그 꼬리 요청과 러너 확인 요청을 ssh로 처리해 결과를 DB에 쓴다(Q61). 요청은 한 번만 처리한다.

## 완료 조건

- 가짜 어댑터로 런 시작·종료 때 트래커 호출이 각각 한 번씩(상태 변경, 댓글)만 일어나고, 댓글을 단 직후 데몬을 다시 띄워도 댓글이 하나라는 테스트가 통과한다.
- 러너 연결 끊김 런의 워크트리가 러너가 다시 Online이 된 뒤 지워진다는 테스트가 통과한다.
- 결과별로 워크트리를 지우거나 남기고, 남긴 런의 PR이 병합·닫힘으로 바뀌면 기록하고 지운다는 테스트가 통과한다.
- DB에 넣은 로그 꼬리 요청·러너 확인 요청이 처리돼 결과가 써진다는 테스트가 통과한다.
