# 데스크톱 앱 (Electron 앱과 분리된 상시 서버)

> **보류 해제(운영자 지시 2026-11-18).** 선행 0029·0048이 끝나 보류를 풀었다. 릴리스는 하지 않는다: 자동 업데이트 피드, GitHub Releases 업로드, 태그, 서명·공증은 아래 「후속(릴리스 때)」로 옮겼다. 앱은 로컬에서 서명 없이 패키징해 시험했고 산출물은 어디에도 올리지 않았다.

## 목표

운영자가 저장소를 빌드하지 않고 데스크톱 앱으로 설치해 쓴다. 앱은 이 기계에서 서버(②)를 돌리거나, 다른 기계의 서버(예: 상시 기계의 ③)에 붙는다. 앱을 닫거나 업데이트해도 서버와 worker는 계속 돈다.

## 배경

research [0012](../research/0012-desktop-app-packaging.md) 5절의 운영자 결정(2026-11-18)을 따른다.

- ① Electron 앱(창·트레이·알림)과 ② 앱에서 분리된(detached) 서버·worker 프로세스로 나눈다. Orca 앱이 창과 별도의 상시 터미널 호스트를 두어 업데이트 뒤에도 세션이 이어지는 방식에서 옮겨 온 판단이다(research 0012 1절. Orca가 다시 붙는 방법은 확인하지 않았다).
- ③ 헤드리스 서비스(CLI `service install`, `apps/cli/src/service.ts`)는 그대로 둔다. 24시간 켜 두는 기계는 ③, 노트북에서 직접 쓰기는 ①+②다. ②와 ③은 같은 서버 코드(`apps/cli/src/start.ts`)를 띄우는 방식만 다르다.
- 도구는 Electron이다. Node 24와 `node:sqlite`가 그대로 돌고, 고치지 않은 CLI `start`를 Electron 안에서 띄웠다(research 0012 2절).
- 원격 모드의 발견·연결은 research [0013](../research/0013-remote-client-pairing.md)을 따른다.

## 범위

- **①+② 구조.** 앱(①)은 창·트레이·알림만 맡고, 서버(②)는 `start`가 띄우는 web + worker다. 서버 코드는 ③과 공유하고, 앱 전용으로 갈라 쓰지 않는다. 앱은 0029의 서버 배포물(`pnpm run bundle`의 폴더)을 고치지 않고 리소스로 싣는다. 배포물에는 Node가 없어, ②를 띄울 Node(Electron의 Node 또는 따로 싣는 Node)는 아래 「②의 detach」에서 정한다. 앱 창은 서버의 web 화면을 그대로 연다(Q1). 앱 전용 화면은 첫 실행·연결 화면뿐이다.
- **두 모드(Q2).** "이 기계에서 서버 돌리기(②)"와 "다른 서버에 붙기(원격)". 첫 실행에서 고르고, 앱 설정과 트레이에서 바꾼다. 원격 모드의 트레이는 서버 상태만 보이고 켜고 끄기는 하지 않는다.
- **원격 모드 연결((a)+(b), 운영자 결정 2026-11-18).** (b) 로컬 Tailscale CLI(`tailscale status --json`, macOS는 배포판마다 경로가 다르다)로 tailnet 기기 목록을 읽고, Online 기기마다 신원 확인 경로를 짧은 시간 제한으로 물어 우리 서버만 목록에 보인다. 한 번 클릭으로 붙는다. Tailscale이 없거나 꺼졌거나 서버를 못 찾으면 (a) 주소를 직접 넣는다. 고른 서버는 기억해 다음 실행에서 바로 열고, 닿지 않으면 같은 서버를 다시 찾은 뒤 "서버에 닿지 않아요" 화면을 보인다. 추가 로그인(Tailscale API 키·OAuth, tsnet)은 쓰지 않는다. 흐름과 상태별 안내는 research 0013 2.1절·4절.
- **신원 확인 경로.** 0048이 만든 `GET /api/identity`를 쓴다(계약은 [0048](0048-server-external-address-and-host-check.md) 「신원 확인 경로 계약」). (b)의 거르기, (a)의 연결 확인, 버전 차이 알림이 쓴다. 응답의 `webAccess`가 `host-not-allowed`면 목록에 서버를 보이되 "그 서버의 Settings > 주소에서 다른 기기에서 열 주소를 정하세요"를 안내한다.
- **(b)의 기본 질의(Q13).** Online 기기마다 `http://<기기>:3000/api/identity`를 먼저, 그다음 `https://<기기>/api/identity`(Tailscale Serve, 443)를 묻는다. 기기당 시간 제한은 1초다. `DNSName` 끝의 점은 뗀다.
- **②의 detach.** 앱이 ②를 앱 프로세스의 자식이 아니게 띄워, 앱이 끝나거나 다시 떠도 ②가 멈추지 않는다. Electron `runAsNode` fuse를 끌지, ②를 Node로 띄울 방법을 무엇으로 할지 여기서 정한다(research 0012 「남은 위험」).
- **재접속과 두 벌 실행 막기.** 앱은 열릴 때 home(`~/.factory-orchestrator` 또는 설정한 경로)의 잠금 파일·포트로 도는 ②를 찾아 붙고, 없을 때만 띄운다. 같은 home에 ②가 둘 뜨지 않게 하고, 같은 기계에 ③이 이미 돌면 ②를 띄우지 않고 ③에 붙는다. ③은 launchd·systemd가 다시 띄우므로(`apps/cli/src/service.ts`), ③에 붙었을 때 트레이는 상태만 보이고 켜고 끄기와 버전 교체는 하지 않는다. 앱에 실린 서버 코드와 ③의 버전이 다르면 알리기만 한다.
- **②의 감시.** ②가 실패로 끝났을 때 누가 다시 띄울지 정한다(앱이 열려 있을 때 앱 등). 로그인 때 ② 띄우기는 Q5로 정했다(기본 켬).
- **②의 버전 교체.** 앱 업데이트로 서버 코드가 바뀌면 옛 ②를 멈추고 마이그레이션 뒤 새 ②를 띄운다. worker 두 벌이 같은 DB를 폴링하지 않게 한다. 도는 런은 러너에서 계속 돌고, 새 worker가 DB의 상태에서 이어서 감시한다(`apps/worker/src/worker.ts`). 교체하는 동안 실패한 webhook은 폴링 보정이 메운다(ADR 0001).
- **트레이.** ②의 상태(돌고 있음·멈춤·실패)를 보이고 켜고 끈다. 창을 닫아도 트레이에 남는다. 트레이 "종료"는 앱만 끝내고 ②는 계속 돈다. "서버도 끄고 종료"를 따로 둔다(Q5). 화면 문구는 메시지 파일로 둔다(ADR 0005).
- **로그인 때 실행(Q5).** 로컬 모드의 첫 실행에서 "로그인 때 ② 띄우기"를 묻고 기본은 켬이다.
- **알림(Q4).** 질문 대기, 권한 대기, Human Check, 러너 Offline만 알린다. Merged·Failed는 알리지 않는다. 앱이 서버에서 이 사건을 받는 방법(폴링 또는 스트림)을 여기서 정한다. 원격 모드에서도 같다.
- **잠자기(Q6).** 앱은 잠자기를 막지 않는다. 24시간 감시가 필요하면 ③(상시 기계)을 안내한다.
- **로그인 없음(Q3).** 앱과 서버에 로그인을 더하지 않는다. tailnet 안의 기기를 믿는다. tailnet을 함께 쓰면 Tailscale ACL로 접속을 막으라는 경고는 README Self-hosting에 둔다(앱 티켓 범위가 아니다).
- **서명(Q8).** 서명 인증서에 계정 이름이 보이는 것은 받아들인다. 이번에는 서명 없이 개발용으로 만든다. 서명 키·팀 ID 같은 값은 저장소에 넣지 않는다. 서명·공증과 자동 업데이트는 「후속(릴리스 때)」.
- **지원 플랫폼(Q7).** 앱은 macOS부터다. Linux 앱은 후속이고, Linux 서버는 ③을 쓴다.
- README에 앱을 로컬에서 빌드·실행하는 법, 두 모드, ①+②·③ 중 무엇을 고를지, 원격 모드에 권장하는 Tailscale Serve 구성을 영어로 쓴다.

## 정한 것 (구현, 2026-11-18)

- **패키지와 나누기.** `apps/desktop`. Electron 없이 도는 모듈(`src/core`: ②의 찾기·띄우기·멈추기·바꾸기, 감시, Tailscale 읽기, 서버 찾기, 원격 연결, 알림 고르기, 앱 설정)과 Electron에 닿는 곳(`src/main`, `src/preload`, `src/renderer`)을 나눴다. `src/core`는 vitest로 실제 프로세스를 띄워 시험한다(서버 배포물 자리에 잠금 계약만 흉내 낸 `testing/fake-server-cli.mjs`). 실제 배포물·패키징한 앱으로 도는 확인은 로컬 `pnpm --filter @factory/desktop smoke`(`smoke/*.smoke.ts`)이고 CI에서는 돌지 않는다. CI의 `pnpm build`는 앱의 Vite 빌드만 하고 Electron 바이너리를 받지 않는다(pnpm이 electron의 설치 스크립트를 돌리지 않는다).
- **패키징 도구: `@electron/packager`.** 서명·업데이트를 하지 않는 이번 범위에는 .app을 만드는 일만 필요하다. 의존성이 가장 적고 research 0012 스파이크에서 5초에 .app을 만든 도구다. electron-builder는 dmg·업데이트 피드·서명을 한데 묶어 의존성이 크고, Electron Forge는 packager를 감싼 도구라 릴리스(0031) 때 메이커·퍼블리셔·서명이 필요하면 packager 설정을 그대로 옮길 수 있다. `scripts/package.ts`가 앱 `dist/`와 `assets/`만(node_modules 없이) 싣고, 서버 배포물을 고치지 않고 `Contents/Resources/server/`에 싣고, `ditto`로 zip을 만든다. 크기는 .app 264MB, zip 128MB(macOS arm64).
- **②의 detach.** 앱 실행 파일을 `ELECTRON_RUN_AS_NODE=1`로 Node처럼 써서 배포물의 CLI `start --home <home>`을 `detached`(새 세션·프로세스 그룹)로 띄우고 놓는다. `runAsNode` fuse는 끄지 않는다. 끄면 이 방법이 막히고, 끄지 않아 생기는 일(이 앱 실행 파일을 누구나 Node로 쓸 수 있음)은 이 기계에 Node가 깔린 것과 같은 수준이라 받아들인다. `utilityProcess`는 앱의 자식이라 앱과 함께 끝나 ②에 맞지 않는다.
- **잠금 파일(서버 실행 계약).** `start`가 마이그레이션 전에 `<home>/server.lock`(`{ pid, url, startedAt }`)을 `wx`로 쥐고 자식이 모두 끝나면 놓는다(`apps/cli/src/server-lock.ts`). 살아 있는 주인이 쥐었으면 두 번째 `start`는 마이그레이션 전에 실패한다. 적힌 프로세스가 없거나, 그 pid가 잠금을 쓴 뒤에 시작한 다른 프로세스면(재부팅 뒤 pid 재사용, `ps`의 시작 시각으로 가린다) 낡은 잠금이다. 낡은 잠금은 치우기 파일(`server.lock.break`)을 쥔 쪽만 다시 읽어 확인한 뒤 지워, 다른 `start`가 막 쓴 잠금을 지우지 않는다. ②와 ③이 같은 코드라 같은 home에 web·worker가 한 벌만 뜬다. 앱은 이 잠금으로 도는 서버를 찾는다. 잠금이 없어도 `.env`의 포트에서 우리 서버가 답하면(잠금을 쓰기 전 버전의 ③ 등) 붙기만 한다.
- **누가 띄운 ②인가.** 앱이 띄운 `start`의 pid, 띄운 시각, 배포물 폴더와 지문(파일 내용 해시, `version+해시`)을 앱 데이터 폴더의 `server-process.json`에 적는다. pid가 다른 프로세스에 다시 쓰였으면(시작 시각이 띄운 시각보다 늦다) 앱의 ②로 보지 않고 신호도 보내지 않는다. 잠금의 pid가 그것과 같으면 앱이 켜고 끄고 바꾸며, 다르면(③, 터미널의 `start`) 상태만 본다. 이 home에 launchd 서비스(③)가 등록돼 있으면 돌지 않을 때도 ②를 띄우지 않는다(서비스 관리자가 띄운다).
- **②의 버전 교체.** 앱이 띄운 ②의 배포물 지문이 앱에 실린 것과 다르면 옛 `start`에 SIGTERM을 보내 끝나기(잠금을 놓기)를 기다린 뒤 새 `start`를 띄운다. 새 `start`가 마이그레이션을 돌린다. 교체 중 worker는 한 벌을 넘지 않는다. ③의 버전이 다르면 알림을 한 번 띄우고 트레이에 적기만 한다.
- **②의 감시.** 앱이 열려 있는 동안 앱이 5초마다 본다. 앱이 띄운 ②가 사람이 멈추지 않았는데 사라지면 다시 띄운다. 2분 안에 세 번 넘게 끝나면 그만두고 "띄우지 못했어요"를 보인다. `start`만 SIGKILL로 끝나 web·worker가 남았으면(같은 프로세스 그룹) 그룹째 멈춘 뒤 다시 띄운다. 앱이 닫혀 있으면 아무도 다시 띄우지 않는다. 24시간 지켜야 하면 ③을 쓴다(README).
- **로그인 때 실행(Q5).** 로컬 모드 첫 화면의 "로그인할 때 서버 띄우기"(기본 켬)가 앱을 로그인 항목으로 등록한다. 로그인 때 뜬 앱은 창 없이 ②를 띄운다. 패키징한 앱에서만 등록한다.
- **알림(Q4) 받는 방법: 폴링.** 서버에 `GET /api/attention`을 더했다(`apps/web/src/attention`, 화면과 같은 Host 검사). 응답 `{ events: [{ kind, key, … }] }`의 `kind`는 `question`·`permission`·`human-check`·`runner-offline` 넷뿐이다. 앱은 연 서버(로컬·원격 같음)를 15초마다 묻고 앞 응답에 없던 `key`만 알린다. 앱을 연 뒤 첫 응답은 기준으로만 삼는다. 알림 제목은 ADR 0010을 따라 Question·Permission·Human Check·Runner Issue다. 누르면 그 런(또는 Runners) 화면을 연다. 스트림은 서버에 연결 상태를 두게 돼 더 크고, 사람이 볼 알림에는 15초가 충분하다.
- **원격 모드.** Tailscale CLI는 `FACTORY_TAILSCALE_CLI`, `/usr/local/bin/tailscale`, `/opt/homebrew/bin/tailscale`, `/Applications/Tailscale.app/Contents/MacOS/Tailscale` 순으로 찾는다. 서버 찾기 포트는 바꿀 수 있고(research 0013 「다른 포트로 찾기」) 앱 설정에 기억한다. 저장한 서버가 닿지 않으면 같은 instanceId를 tailnet에서 다시 찾고, 그래도 없으면 "닿지 않아요" 화면에서 5초마다 다시 본다.
- **앱 창.** 창 하나가 앱 화면(첫 실행, 서버 찾기, 주소로 연결하기, 닿지 않음, 로컬 서버 상태)과 서버의 web 화면을 번갈아 연다. 앱 화면에만 preload API를 연다. 서버 밖으로 나가는 링크는 브라우저로 연다. 트레이 메뉴와 메뉴 막대 "서버" 메뉴는 같은 항목이다.

## 남은 위험

- 실제 tailnet(다른 기기, Tailscale Serve HTTPS)으로는 돌려 보지 않았다. 흉내 낸 `tailscale status --json`과 이 기계의 loopback으로만 시험했다.
- 로그인 항목 등록(`setLoginItemSettings`)과 로그인 때 창 없이 뜨기는 서명하지 않은 앱에서 돌려 보지 않았다. macOS 13 이후 로그인 항목은 서명에 기댈 수 있다.
- 앱이 닫혀 있는 동안 ②가 죽으면 다시 띄우는 것이 없다(감시는 앱이 열린 동안만). 다음에 앱을 열 때 다시 띄운다.
- `start`만 SIGKILL로 끝나면 web·worker가 남는다. 앱이 띄운 ②는 앱이 그 프로세스 그룹에서 기록한 배포물 폴더로 뜬 것만 골라 치운 뒤 다시 띄운다. 터미널에서 띄운 `start`는 아무도 치우지 않아, 그 뒤 새 `start`가 낡은 잠금을 쥐면 worker가 잠시 두 벌일 수 있다. ③은 launchd·systemd가 서비스의 프로세스를 함께 거둔다.
- 앱 데이터 폴더의 기록(`server-process.json`)을 지우면 앱이 자기 ②를 ③처럼 보고 켜고 끄기·교체를 하지 않는다. 앱을 다시 설치해도 앱 데이터는 남는다.
