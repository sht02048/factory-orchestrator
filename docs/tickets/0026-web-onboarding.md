# web 온보딩

## 목표

첫 진입 때 사이드바 없는 전체 화면에서 필수 설정을 끝낸다.

## 범위

- 이 티켓은 `apps/web`의 온보딩 라우트, 그 화면 메시지, 루트 라우트(`__root.tsx`)에 온보딩이 끝나지 않았으면 온보딩으로 보내는 처리만 고친다. 앱 셸 중 이 처리만 0007 밖에서 더한다. 입력 폼과 연결 확인은 Settings(0025)의 것을 다시 쓴다.
- 트래커 연결 → GitHub 토큰 → 첫 러너 등록과 ssh 확인 → 첫 Workspace(트래커 프로젝트 고르기) → 첫 Mapping. 모든 단계가 필수이고 확인이 성공해야 다음으로 간다(ADR 0005·0007).
- GitHub 토큰 단계는 필수 권한(Metadata, Pull requests 읽기)을 안내하고 연결을 확인한다. Actions 읽기는 선택이며, 더하면 Run 상세에서 CI 상태를 볼 수 있다고 안내한다(Q79). 권한은 저장소마다 달라 이 단계에서 선택 권한을 확인하지 않는다.
- 러너 단계는 스펙 9절의 러너 필수 조건을 확인한다(Q43). 확인은 worker가 한다(Q61).
  - Orca 상시 서비스가 없으면 설치 명령 `orca serve service install`을 안내한다. 러너의 PATH에 Orca CLI(macOS `orca`, Linux는 확인 전이나 help에 따르면 `orca-ide`)가 없으면 `--command <orca 절대 경로>`를 함께 안내한다(research 0003 6·7절). Orca 1.4.258에는 `--supervise` 플래그가 없다.
  - 비대화형 ssh 세션에서 러너의 GitHub 인증이 동작하는지 러너 쪽 프로젝트 저장소마다 `git push --dry-run`으로 확인하고(Q82.15, 0013), 안 되면 그 사실과 흔한 원인(gh 토큰 무효, macOS 키체인 잠김, GitHub용 ssh 키 없음), 해결 방법(`gh auth login --insecure-storage`와 `gh auth setup-git`, 또는 GitHub용 ssh 키)을 보인다. 에이전트가 러너에서 push·PR을 해야 PR 상태를 정할 수 있다.
- Mapping 단계는 에이전트가 쓸 권한을 그 프로젝트의 에이전트 설정에서 미리 허용하기를 권한다. 오케스트레이터 화면에서는 권한 프롬프트를 거절만 할 수 있고 허용은 러너 화면에서 사람이 해야 한다. 오케스트레이터는 권한 전체 우회를 쓰지 않는다(Q82.4).
- Mapping 단계는 에이전트가 PR 제목에 티켓 키를 넣도록 그 프로젝트의 에이전트 지침에 적기를 권한다. 쓰지 않으면 에이전트가 다른 브랜치로 PR을 열거나 브랜치 이름을 바꾼 런의 PR을 찾지 못해, PR 상태가 "없음"이나 "닫힘"으로 잘못 기록된다(research 0006 17절). 이 제품은 프로젝트의 에이전트 설정을 고치지 않는다(ADR 0004).
- Linear webhook을 운영자가 Linear 설정에서 만드는 방법과 받을 경로를 안내한다(research 0002 B.2). 밖에서 닿는 공개 주소는 운영자가 고른 방법(ADR 0005)에 달려 있어 화면은 지금 접속한 주소를 예로 보인다.

## 완료 조건

- 설정이 없는 DB로 아무 화면에 들어가도 온보딩으로 간다는 테스트가 통과한다.
- 확인이 실패한 단계에서 다음으로 갈 수 없다는 테스트가 통과한다. 러너 단계는 Orca 상시 서비스가 없을 때와 GitHub 인증이 안 될 때를 각각 다룬다.
- 다섯 단계를 마치면 홈으로 가고, 그 뒤에는 온보딩이 뜨지 않는다는 테스트가 통과한다.
