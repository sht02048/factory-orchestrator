# core 도메인 규칙과 어댑터 인터페이스

## 목표

런의 상태와 결과를 정하는 규칙을 외부 시스템 없이 순수 함수로 만들고, 나머지 패키지가 기대어 쓸 어댑터 인터페이스와 테스트용 가짜 어댑터를 `packages/core`에 둔다. 이후 db·worker·web·어댑터 티켓이 이 타입을 함께 쓴다.

## 범위

- 이 티켓은 `packages/core`만 고친다.
- 도메인 타입: Run, Run 상태(Queued, Running, Waiting for Input, Ended), 결과(Merged, Human Check, Failed), Failed 사유 다섯(PR 없음, 에이전트 오류, 러너 연결 끊김, PR이 닫힘, 시간 초과). 이름은 GLOSSARY를 따른다.
- 상태 전이 함수: 허용하지 않는 전이를 거부한다(스펙 4.1).
- 판정 함수 `JudgeRunOutcome`: 스펙 4.2 판정 표 그대로. 시간 초과 런의 PR이 열려 있으면 워크트리를 남기라는 값도 돌려준다(Q51).
- 할당 조건(Auto-assign Label, 티켓당 진행 중이거나 Queued인 런 하나, Q45), 할당 때의 러너 고르기(러너 쪽 프로젝트가 있는 Online 러너 중 남은 capacity가 가장 많은 러너, Q53. 그런 러너가 없을 때는 스펙 11절 열린 질문 2), FIFO 대기열 꺼내기(ADR 0006). 순서대로 훑되 시작할 수 있는 런부터 시작하고, 같은 러너를 기다리는 런끼리는 들어온 순서를 지킨다(Q63).
- 시간 초과 판단(Waiting for Input 포함, Q39·Q52), 러너 연결 끊김 판단(ssh 5분 연속 실패, Q50), 리드 타임·대기 시간·실행 시간 계산(Q59).
- 어댑터 인터페이스 `Tracker`, `Runner`, `CodeHost`: research 0002 「어댑터 인터페이스 초안」에서 출발하고, 스펙 5절이 더한 것(에이전트 멈추기, 로그 꼬리, 에이전트 종료 코드, 입력 기다림, 티켓 키로 PR 찾기)을 담는다. 외부 열거값은 열어 둔다.
- 세 인터페이스의 가짜 구현(메모리 안에서 동작, 테스트가 응답을 정할 수 있음). 끝에서 끝까지 얇은 경로(0006·0007·0008)가 이것으로 돈다.

## 완료 조건

- 판정 표 여덟 줄이 각각 테스트 하나로 통과하고, 0이 아닌 종료 코드에 PR이 있는 경우 PR 상태로 판정된다는 테스트가 통과한다(Q62).
- 맨 앞 런의 러너가 꽉 찼을 때 다른 러너의 뒤 런이 먼저 시작하고, 같은 러너를 기다리는 런은 순서를 지킨다는 테스트가 통과한다(Q63).
- 상태 전이, 할당 조건, 러너 고르기, FIFO, 시간 초과, 러너 연결 끊김(4분 59초는 이어서 봄, 5분은 끊김), 리드 타임 계산이 테스트로 통과한다.
- 가짜 어댑터 셋이 인터페이스를 만족한다는 것이 typecheck로 확인된다.
