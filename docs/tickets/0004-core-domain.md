# core 도메인 규칙과 어댑터 인터페이스

## 목표

런의 상태와 결과를 정하는 규칙을 외부 시스템 없이 순수 함수로 만들고, 나머지 패키지가 기대어 쓸 어댑터 인터페이스와 테스트용 가짜 어댑터를 `packages/core`에 둔다. 이후 db·worker·web·어댑터 티켓이 이 타입을 함께 쓴다.

## 범위

- 이 티켓은 `packages/core`만 고친다.
- 도메인 타입: Run, Run 상태(Queued, Running, Waiting for Input, Disconnected, Ended), 에이전트 결과 여섯(정상 종료, 오류 종료, 시간 초과, 입력 기다리다 멈춤, 러너 연결 끊김, 워크트리 없음), PR 상태 넷(없음, 열림, 병합됨, 닫힘), 요약 결과(Merged, Human Check, Failed). Failed 사유 타입은 두지 않는다(Q71). 이름은 GLOSSARY를 따른다.
- 상태 전이 함수: 허용하지 않는 전이를 거부한다. Running·Waiting for Input ⇄ Disconnected를 포함한다(스펙 4.1, Q67).
- PR 상태 정하기: 런과 이어진 PR 목록에서 PR 상태 하나를 정한다(같은 브랜치에 여럿이면 가장 최근 것, 스펙 4.2).
- 요약 계산 함수(`summarizeRunOutcome`): 에이전트 결과와 PR 상태를 받아 스펙 4.2 요약 계산 표 그대로 요약 결과와 워크트리 처리(바로 지움, PR이 병합되거나 닫힐 때까지 남김, 사람이 정함, 지울 것 없음)를 돌려준다(Q51·Q66·Q71·Q75). CODING_STANDARDS 「요약 결과는 계산 함수 하나로만 정한다」.
- 할당 조건(Auto-assign Label, 티켓당 진행 중(Running, Waiting for Input, Disconnected)이거나 Queued인 런 하나, Q45·Q74), 할당 때의 러너 고르기(러너 쪽 프로젝트가 있는 Online 러너 중 남은 capacity가 가장 많은 러너, Q53. 그런 러너가 없으면 러너를 정하지 않은 Queued로 두고 맞는 러너가 Online이 될 때 같은 규칙으로 고른다, Q65), 엄격한 FIFO 대기열 꺼내기(ADR 0006). 맨 앞 런이 시작될 때까지 뒤 런은 러너와 상관없이 기다린다(Q63 개정). 러너 없는 Queued 런은 순서에서 빠지고, 할당 때 정한 러너가 Offline이 된 Queued 런은 러너를 비워 같이 다루며, 맞는 러너가 Online이 되면 러너를 정해 원래 들어온 자리로 돌아간다(Q68·Q72·Q73). Disconnected 런은 capacity를 차지한다(Q74).
- 시간 초과 판단(Waiting for Input·Disconnected 포함, 멈출 때의 상태로 시간 초과·입력 기다리다 멈춤·러너 연결 끊김을 가름, Q39·Q52·Q67·Q70), 연결 끊김 판단(ssh 5분 연속 실패면 Disconnected, Q50·Q67), 다시 연결했을 때 실제 상태(에이전트 돌고 있음, 끝남, 워크트리 사라짐)에서 다음 상태나 에이전트 결과를 정하는 함수(Q67), 리드 타임·대기 시간·실행 시간 계산(Q59).
- 어댑터 인터페이스 `Tracker`, `Runner`, `CodeHost`: research 0002 「어댑터 인터페이스 초안」에서 출발하고, 스펙 5절과 뒤 티켓이 쓰는 것(에이전트 멈추기, 로그 꼬리, 에이전트 종료 코드, 입력 기다림, 티켓 키로 PR 찾기, PR 번호로 PR 조회, 트래커 프로젝트의 티켓 목록, Tracker·CodeHost 연결 확인, 러너의 Orca 상시 서비스 설치 여부)을 담는다. 외부 열거값은 열어 둔다.
- 세 인터페이스의 가짜 구현(메모리 안에서 동작, 테스트가 응답을 정할 수 있음). 가짜 Runner는 따로 정하지 않으면 Online이고 테스트가 넣은 러너 쪽 프로젝트를 가진다고 답한다. 그래야 worker가 러너 상태를 주기적으로 확인해도(0016) 얇은 경로 시험(0008)이 깨지지 않는다. 끝에서 끝까지 얇은 경로(0006·0007·0008)가 이것으로 돈다.

## 완료 조건

- 에이전트 결과 여섯 × PR 상태 넷의 모든 조합(스물넷)이 요약 계산 표대로 요약 결과와 워크트리 처리를 돌려준다는 테스트가 통과한다. 오류 종료 + 열림이 Human Check라는 경우를 따로 확인한다(Q66).
- 맞는 러너가 모두 Offline이면 러너 없는 Queued가 되고, 러너가 Online이 되면 그 러너로 정한다는 테스트가 통과한다(Q65·Q68).
- 맨 앞 런의 러너가 꽉 찼을 때 다른 러너의 뒤 런도 기다린다는 테스트가 통과한다(Q63 개정).
- 러너 없는 Queued 런이 맨 앞에 있어도 뒤 런이 시작하고, 정한 러너가 Offline이 된 Queued 런은 러너가 비워지며, 러너가 Online이 되면 그 런이 원래 자리로 돌아가 (그 러너에 capacity가 있으면) 뒤 런보다 먼저 시작한다는 테스트가 통과한다(Q68·Q72·Q73).
- 상태 전이, 할당 조건(Disconnected 런이 있는 티켓은 할당 안 됨), 러너 고르기, 시간 초과(Running·Waiting for Input·Disconnected에서 각각 맞는 에이전트 결과), 연결 끊김(4분 59초는 이어서 봄, 5분은 Disconnected), 다시 연결 세 경우, 리드 타임 계산이 테스트로 통과한다.
- 가짜 어댑터 셋이 인터페이스를 만족한다는 것이 typecheck로 확인된다.
