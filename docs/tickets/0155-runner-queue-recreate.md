# 0155 대기열과 다시 만든 워크트리

## 목표

이어서 맡긴 런이 꽉 찬 러너를 기다리는 동안 다른 런이 빈 러너에서 시작하게 하고, 이어서 맡기기로 다시 만든 워크트리에서도 저장소 설정 스크립트를 돌린다(운영자 결정 F3·F4, 2026-11-21).

## 배경

대기열은 설치 전체에 하나인 엄격한 FIFO라, 맨 앞 런의 러너가 꽉 차면 다른 러너가 비어 있어도 뒤 런이 모두 기다렸다. 이어서 맡긴 런은 러너에 고정되어(0149) 이 막힘이 길어진다.

이어서 맡기기는 Orca `worktree create --branch`가 이미 있는 브랜치에 다른 이름을 붙이기 때문에 `git worktree add`로 워크트리를 다시 만든다. 그래서 Orca의 저장소 설정 훅이 돌지 않아 의존성 없는 워크트리에서 에이전트가 시작했다. Orca의 `worker-start`도 이미 있는 워크트리에서는 setup을 돌리지 않는다.

## 할 일

1. F3: 대기열을 러너별로 세운다. 앞 런이 기다리는 러너만 뒤 런에게 막히고, 고정된 런은 자기 러너 자리만 기다린다. 러너를 아직 정하지 않은 런은 자리가 비어 있고 기다리는 런이 없는 러너로 먼저 간다.
2. 대기 이유도 러너별로 보인다. 러너에서 처음 기다리는 런은 자리 없음, 그 뒤 런은 앞 런을 기다림이다.
3. F4: 다시 만든 워크트리에서 Orca와 같은 규칙으로 setup 명령을 정해 돌린다. 끝나기 전에는 에이전트를 시작하지 않는다.
4. F4: setup이 실패하거나 결과를 모르면 그 런을 시작할 수 없음(Failed)으로 끝내고 이유를 Run 상세에 보인다. 워크트리가 남아 있어 다시 만들지 않았으면 돌리지 않는다.
5. ADR 0006, 스펙 0006 C5-2, GLOSSARY의 대기열·이어서 맡기기 설명을 맞춘다.

## 완료 조건

- 시험: 고정 런이 꽉 찬 러너를 기다리는 동안 다른 런이 빈 러너로 시작한다.
- 시험: 다시 만든 워크트리에서 setup이 돌고, 실패하면 시작 실패로 끝나며, 워크트리가 남아 있으면 돌지 않는다.
- 화면 변경 없음(기존 시작 오류 구역에 이유가 보인다). DB 변경 없음.
