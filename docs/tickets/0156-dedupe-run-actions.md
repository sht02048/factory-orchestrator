# 0156 중복 요청 막기

## 목표

같은 동작을 두 번 눌러도 한 번만 처리한다(운영자 결정 F5, 2026-11-21).

## 배경

0147의 에이전트에게 보내기는 요청 ID로 같은 요청을 한 번만 처리한다. 워크트리 지우기, Human Check 답, 런 쓰기 동작에는 이 보호가 없어 더블클릭이나 다시 보내기로 같은 일이 두 번 일어날 수 있다.

## 할 일

1. 화면: 요청을 보내는 동안 버튼을 막는다.
2. 서버: 같은 요청 ID를 한 번만 처리한다(0147 방식).
3. 적용 대상: 워크트리 지우기, Human Check 답, 런 쓰기 동작(취소, 멈추기, 답하기, 이어서 맡기기).

## 완료 조건

- 시험: 동작마다 같은 요청 ID를 두 번 보내도 한 번만 처리하고 같은 결과를 돌려준다.
- 시험: 보내는 동안 버튼이 막힌다.

## 구현 메모

- 요청 ID는 런별 표 `run_action_requests`에 둔다. 성공한 요청만 적으므로, 거절된 요청은 같은 ID로 다시 보내면 지금 상태로 다시 판단한다.
- 같은 ID로 다른 동작이나 다른 내용을 보내면 처리하지 않고 거절한다.
- 화면은 응답을 받지 못한 요청의 ID를 60초 동안 지켜 다시 보낼 때 쓴다.
- MCP의 `answer_question`, `cancel_run`은 선택 인자 `requestId`로 같은 규칙을 쓴다. 나머지 대상 동작은 MCP 쓰기 도구가 없다.

## 마이그레이션(one-way)

- `20261121094045_run_action_requests`는 표와 유일 인덱스를 더하기만 하고 기존 데이터를 바꾸지 않는다.
- 되돌리는 법: 서버를 끄고 DB를 백업한 뒤 이전 버전으로 돌린다. 마이그레이션 기록까지 되돌려야 하므로 백업 복원이 가장 안전하다. 복원하면 백업 뒤의 런 기록은 사라진다.
