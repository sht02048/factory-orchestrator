# 0146 Workspace 티켓 앞뒤 지시와 런이 받은 지시서

## 목표

운영자가 Workspace마다 티켓 앞뒤 지시를 정하고, 에이전트가 받을 지시서를 미리 본다. 런마다 받은 지시서를 저장해 Run 상세에 보인다. 스펙 [0006](../spec/0006-agent-control.md) C0·C1·C2(운영자 결정 2026-11-21). 이 PR에서 스펙 0006, ADR [0023](../adr/0023-human-check-request.md), GLOSSARY, 후속 티켓 0147~0150 문서도 함께 쓴다.

## 배경

Ganger의 지시서는 티켓과 통신 규약뿐이다(C0). 작업을 어떻게 끝낼지(push, PR, 검사)는 프로젝트 규칙에 있어야 하는데, 규칙이 없는 저장소나 Workspace마다 늘 덧붙이고 싶은 말이 있으면 쓸 자리가 없다. 0.2.0의 DEE-12 런처럼 에이전트가 push·PR 없이 끝나는 일을 운영자가 지시로 막을 길도 없다.

## 할 일

1. Workspace에 앞뒤 지시를 저장한다. `workspaces.brief_before`·`brief_after`(빈 문자열 기본). 각 칸 8,000자(유니코드 문자 수), web 서버 함수 경계에서 zod로 검사하고 앞뒤 빈 줄을 다듬어 저장한다. 이름·최대 실행 시간 저장은 앞뒤 지시를 건드리지 않는다.
2. 지시서 합치기를 `packages/core/src/agent-brief.ts` 한 곳에 둔다. 앞 지시 → 티켓 → 뒤 지시 → 통신 규약, 빈 칸은 뺀다. 통신 규약은 러너 어댑터가 낸다(`Runner.agentProtocol`, Orca는 `ASK_GUIDE`). worker가 시작 명령 직전에 합쳐 `runs.agent_brief`에 저장하고 러너에 넘긴다. 러너 어댑터는 받은 지시서를 그대로 stdin으로 넘긴다. 재개 때 새 에이전트 세션을 띄우면 그 런이 받은 지시서를 다시 보낸다.
3. Settings › Workspace: "에이전트에게 보내는 지시" 줄(ⓘ 툴팁, 요약), 바꾸기로 두 칸과 미리 보기(예시 티켓으로 합친 전체), 저장(0119 Settings 규칙). Run 상세에 "받은 지시서"를 접어서 보인다. 문구는 메시지 파일(ko), 해요체.
4. MCP: `get_settings`의 Workspace 일반 설정에 앞뒤 지시와 통신 규약, `get_run`에 받은 지시서를 보인다. 앞뒤 지시와 받은 지시서는 `external` 칸에 둔다. 쓰기 도구는 더하지 않는다.
5. 데모 시드: 첫 Workspace에 앞뒤 지시 예시, 시작한 런에 받은 지시서.

## 범위 밖

- 통신 규약의 Human Check 문장(0148), 에이전트에게 보내기(0147), 이어서 맡기기(0149), PR 정보(0150).
- en 메시지 파일. 지금 저장소에는 ko 메시지 파일만 있다. en이 생기면 같은 키를 더한다.

## DB 변경과 되돌리는 법

`workspaces`에 `brief_before`·`brief_after`(text, 기본 `''`, NOT NULL), `runs`에 `agent_brief`(text) 열을 더한다(`ALTER TABLE ADD`, 표를 다시 만들지 않는다). one-way 마이그레이션이다. 옛 버전은 새 마이그레이션이 적힌 DB를 다운그레이드로 거부하므로, 되돌리려면 이 버전 전의 DB 백업으로 돌아가야 한다. 백업 뒤에 저장한 앞뒤 지시와 런이 받은 지시서는 잃는다.

## 완료 조건

- 시험: 지시서 합치기(빈 칸, 순서, 길이), 저장·검증(8,000자, 없는 Workspace, 이름 저장이 지시를 지우지 않음), 새 런부터 적용(도는 런은 그대로), Run 상세 받은 지시서, Settings 화면(요약, 미리 보기 순서, 브라우저 편집·저장·길이 초과), 400px, MCP 읽기, 데모 시드.
- 스크린숏: Settings › Workspace 지시 칸과 미리 보기, Run 상세 받은 지시서.
- 화면 변경 있음. DB 변경 있음(one-way).
