# 0.1.0 릴리스

> **보류(운영자 지시 2026-11-18).** 릴리스는 멀었다. 같은 날 운영자 결정으로 0029는 npm 패키지 대신 서버 배포물(공개하지 않음)을 만드는 일로 바뀌었고, npm 공개 여부·Changesets·0.1.0 changeset은 이 티켓으로 옮겼다. 1단계 완료 기준 시험(0030)은 저장소에서 CLI로 띄워 끝냈다(Q90). 보류를 풀 때까지 시작하지 않는다.

> **보류 해제(운영자 지시 2026-11-18).** 이름과 상관없는 일(서명 자리, secret, 버전·변경 기록과 자동 업데이트 결정)부터 한다. 앱 이름·번들 ID·저장소 주소가 들어가는 릴리스 스크립트와 워크플로는 0078·0079 뒤에 만든다.

> **배포 경로 결정(운영자 2026-11-18).** npm으로는 내지 않는다. 0.1.0은 macOS 앱(dmg, Developer ID 서명·공증)만 GitHub Release에 올린다. Linux·macOS 서버 배포물(0029)은 이번 릴리스에 올리지 않는다. 보류는 그대로다. 공개 전에 브랜딩(Ganger, 0076~0079)을 먼저 끝낸다.

> **서명 위치 결정(운영자 2026-11-18, 위 결정의 "서명 맥북에서 릴리스 스크립트를 돌린다"를 바꾼다).** 서명·공증·Release 올리기는 GitHub Actions에서 `v*` 태그를 push할 때만 돈다. PR과 `main` push에서는 돌지 않는다. 운영자의 다른 앱이 이미 같은 방식(태그 push → macOS 러너에서 서명·공증 → Release)으로 공증을 통과했다. 릴리스가 한 기계에 묶이지 않고 과정이 저장소에 남는다. 서명 맥북 점검은 끝났다(Developer ID 인증서 유효, App Store Connect API 키로 만든 notarytool 키체인 프로필로 공증 시험 Accepted). 그 프로필은 로컬 시험용으로 남긴다.

## 목표

1단계를 0.1.0으로 공개한다.

## 범위

- **ADR 0005 고치기.** "npm 패키지 하나와 CLI" 배포 문장을 "macOS 앱(dmg)을 GitHub Release로 배포"로 고친다. CLI와 서비스 등록(launchd·systemd)은 그대로이고, Linux 서버 배포물은 0.1.0에 올리지 않을 뿐 지원을 접는 것이 아님을 함께 적는다.
- **릴리스 스크립트(`pnpm release:mac` 같은 이름).** 순서: 빌드 → `.app` 패키징(0046의 `@electron/packager`) → Developer ID 서명(`@electron/osx-sign`) → 공증(`notarytool`) → 공증 결과를 앱에 붙이기(`xcrun stapler staple`) → dmg 만들기(`hdiutil`) → dmg 서명·공증·staple. 서명 단계는 환경 변수가 없으면 건너뛰고 서명 없는 dmg를 만들어, 서명 없는 맥과 PR CI에서도 앞 단계를 시험할 수 있게 한다.
- **릴리스 워크플로(`.github/workflows/release.yml`).** `push: tags: ["v*"]`에서만 돈다. 태그가 `apps/desktop` 버전과 맞는지 먼저 보고, `ci.yml`을 재사용해 시험을 돌리는 동안 macOS 러너에서 임시 키체인에 인증서를 넣고 릴리스 스크립트를 돌린다. 받은 dmg를 마운트해 `codesign --verify --deep --strict`, `xcrun stapler validate`, `spctl --assess`로 확인한 뒤, 시험과 빌드가 모두 통과해야 `gh release create`로 올린다. 앱 아이콘 `.icon`을 컴파일하려면 Xcode 26 이상이 필요하니, 러너 이미지의 Xcode 버전을 확인해 고른다.
- **비밀 값은 저장소에 넣지 않는다.** 인증서·키·팀 ID는 GitHub `release` environment의 secret으로만 둔다(ADR 0005, AGENTS.md 공개 저장소). environment의 배포 규칙을 `v*` 태그로 묶어, 태그 push가 아닌 워크플로는 secret을 읽지 못하게 한다. 서명 identity는 임시 키체인에서 "Developer ID Application"으로 찾으므로 인증서 이름을 따로 두지 않는다.
  - `MACOS_CERT_P12`: Developer ID Application 인증서와 개인 키를 내보낸 `.p12`의 base64
  - `MACOS_CERT_PASSWORD`: 그 `.p12`의 암호
  - `APPLE_API_KEY`: App Store Connect API 키 `.p8`의 base64
  - `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`: 그 키의 Key ID와 Issuer ID
- **0.1.0 버전과 변경 기록(운영자 결정 2026-11-18).** Changesets와 `CHANGELOG.md`는 두지 않는다. 루트와 `apps/desktop`의 `package.json` 버전을 PR로 올리고 머지한 뒤 `v0.1.0` 태그를 push한다. Release 본문은 `gh release create --generate-notes`가 머지된 PR 제목으로 만든다. 태그에 `-`가 있으면(`v0.1.0-rc.1`) prerelease로 올려, 정식 태그 전에 서명·공증 경로를 시험한다.
- 앱에 묶은 서드파티 코드의 라이선스 고지를 공개 전에 정한다(0029 「남은 위험」).
- web 서버 번들에 남는 빌드 기계의 절대 경로(TanStack Start 매니페스트 `filePath`)를 공개 전에 지운다(0029 「남은 위험」).
- **자동 업데이트는 0.1.0에 넣지 않는다(운영자 결정 2026-11-18).** 0.1.0은 dmg만 올리고, 새 버전은 Release에서 다시 받는다. 업데이트 피드 주소가 저장소 이름(0079)에 달려 있어 [0083](0083-desktop-auto-update.md)으로 옮겼다.
- README에 macOS 앱 설치 안내를 영어로 더한다.
- 운영자 준비(2026-11-18 끝남): 저장소에 `release` environment를 만들고 배포 규칙을 `v*` 태그로 묶은 뒤, 위 secret 다섯 개를 넣었다. `.p12` 암호가 맞는지는 첫 릴리스 워크플로의 인증서 가져오기 단계에서 확인된다. Apple 약관이 바뀌면 공증이 403으로 막히니, 릴리스 전에 developer.apple.com과 App Store Connect Business 화면의 약관 동의를 확인한다.
