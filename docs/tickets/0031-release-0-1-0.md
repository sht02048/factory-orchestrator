# 0.1.0 릴리스

> **보류(운영자 지시 2026-11-18).** 릴리스는 멀었다. 같은 날 운영자 결정으로 0029는 npm 패키지 대신 서버 배포물(공개하지 않음)을 만드는 일로 바뀌었고, npm 공개 여부·Changesets·0.1.0 changeset은 이 티켓으로 옮겼다. 1단계 완료 기준 시험(0030)은 저장소에서 CLI로 띄워 끝냈다(Q90). 보류를 풀 때까지 시작하지 않는다.

> **배포 경로 결정(운영자 2026-11-18).** npm으로는 내지 않는다. 0.1.0은 macOS 앱(dmg, Developer ID 서명·공증)만 GitHub Release에 올린다. Linux·macOS 서버 배포물(0029)은 이번 릴리스에 올리지 않는다. 서명 인증서는 운영자의 다른 맥북 키체인에만 있으므로, CI로 옮기지 않고 그 맥북에서 릴리스 스크립트를 돌린다. 보류는 그대로다. 공개 전에 브랜딩(Ganger, 0076~0079)을 먼저 끝낸다.

## 목표

1단계를 0.1.0으로 공개한다.

## 범위

- **ADR 0005 고치기.** "npm 패키지 하나와 CLI" 배포 문장을 "macOS 앱(dmg)을 GitHub Release로 배포"로 고친다. CLI와 서비스 등록(launchd·systemd)은 그대로이고, Linux 서버 배포물은 0.1.0에 올리지 않을 뿐 지원을 접는 것이 아님을 함께 적는다.
- **릴리스 스크립트(`pnpm release:mac` 같은 이름).** 서명 맥북에서 돌린다. 순서: 빌드 → `.app` 패키징(0046의 `@electron/packager`) → Developer ID 서명(`@electron/osx-sign`, 인증서는 키체인에서 이름으로 찾는다) → 공증(`notarytool`, 키체인 프로필) → 공증 결과를 앱에 붙이기(`xcrun stapler staple`) → dmg 만들기(`hdiutil`) → dmg 서명·공증·staple → `gh release create`로 dmg 올리기. 서명 단계는 환경 변수가 없으면 건너뛰고 서명 없는 dmg를 만들어, 서명 없는 맥에서도 앞 단계를 시험할 수 있게 한다.
- **비밀 값은 저장소에 넣지 않는다.** 인증서 이름, 팀 ID, 공증 프로필 이름은 서명 맥북의 환경 변수·키체인에서만 읽는다(ADR 0005, AGENTS.md 공개 저장소).
- **0.1.0 버전과 변경 기록.** 버전 올리기와 변경 기록 방식을 정한다(Changesets는 npm 공개가 없으면 꼭 필요하지 않으니 이 티켓에서 고른다). `v0.1.0` 태그를 만든다.
- 앱에 묶은 서드파티 코드의 라이선스 고지를 공개 전에 정한다(0029 「남은 위험」).
- web 서버 번들에 남는 빌드 기계의 절대 경로(TanStack Start 매니페스트 `filePath`)를 공개 전에 지운다(0029 「남은 위험」).
- 자동 업데이트(0046 「후속(릴리스 때)」)를 0.1.0에 넣을지 정한다. 서명한 앱이어야 돈다.
- README에 macOS 앱 설치 안내를 영어로 더한다.
- 운영자 준비: 서명 맥북에 Developer ID 인증서와 notarytool 키체인 프로필, `gh` 로그인.

## 완료 조건

- GitHub Release의 0.1.0 dmg를 다른 맥에서 받아 Gatekeeper 경고 없이 열리고, 앱이 서버를 띄운다.
- GitHub에 `v0.1.0` 태그와 변경 기록이 있다.
