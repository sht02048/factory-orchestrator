# 0.1.0 릴리스

> **보류(운영자 지시 2026-11-18).** 릴리스는 멀었다. 같은 날 운영자 결정으로 0029는 npm 패키지 대신 서버 배포물(공개하지 않음)을 만드는 일로 바뀌었고, npm 공개 여부·Changesets·0.1.0 changeset은 이 티켓으로 옮겼다. 1단계 완료 기준 시험(0030)은 저장소에서 CLI로 띄워 끝냈다(Q90). 보류를 풀 때까지 시작하지 않는다.

## 목표

1단계를 0.1.0으로 공개한다.

## 범위

- **배포 경로를 정한다(운영자 결정 필요).** 0029의 서버 배포물(tarball)을 GitHub Release에 올릴지, npm 패키지로도 낼지 정한다. npm으로 내면 배포물 폴더(`package.json`에 의존성이 없고 `bin`이 있다)를 그대로 `npm pack`할 수 있는지 이 티켓에서 확인한다. ADR 0005의 "npm 패키지 하나와 CLI"를 바꾸면 ADR도 고친다.
- Changesets 설정과 0.1.0 changeset(ADR 0005). `changeset status`가 0.1.0을 보여 준다.
- 0.1.0 버전과 변경 기록을 만들고 정한 경로로 공개한다. publish·업로드를 어디서 할지(로컬 또는 GitHub Actions)는 이 티켓에서 정한다. 토큰은 저장소에 넣지 않는다(ADR 0005).
- 배포물에 묶은 서드파티 코드의 라이선스 고지를 공개 전에 정한다(0029 「남은 위험」).
- README Self-hosting 절에 설치·업그레이드 안내를 영어로 더한다.
- 운영자 준비가 필요하다: npm으로 낸다면 npm 계정과 publish 토큰, 패키지 이름이 비어 있는지 확인.

## 완료 조건

- 공개한 0.1.0 배포물을 받아 `init`·`start`가 돈다.
- GitHub에 `v0.1.0` 태그와 변경 기록이 있다.
