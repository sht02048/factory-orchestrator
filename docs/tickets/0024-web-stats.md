# web Stats 화면

## 목표

현재 Workspace의 처리량, 요약 결과 분포, 리드 타임, Human Check 뒤 병합 비율을 본다.

## 범위

- 이 티켓은 `apps/web`의 Stats 라우트와 그 화면 메시지만 고친다. 리드 타임 계산은 core 함수(0004)를 쓴다.
- 처리량, 요약 결과 분포(Merged / Human Check / Failed, core 요약 계산 함수로 계산), Failed 런의 에이전트 결과 × PR 상태 조합별 수(Q71). 운영자가 취소한 런을 분포와 리드 타임에 넣을지는 이 티켓을 닫을 때 정해지지 않았다.
- 후속(Q82, 이 티켓을 닫은 뒤 정함): 요약 결과 Canceled를 "취소"로 따로 세고 성공·실패율에서 빼기, 시작하지 않고 끝난 런의 대기 시간(할당~끝낸 시각)과 실행 시간 0, 에이전트 결과 이름 바뀜(완료 보고, 비정상 종료, 시작할 수 없음)은 후속 티켓 [0038](0038-web-run-decisions-follow-up.md)에서 반영한다(Q82.2·Q82.9·Q82.18·Q82.20).
- 리드 타임은 할당(Queued 포함)부터 런 종료까지이고, 대기 시간과 실행 시간을 나눠 보인다(Q59).
- Human Check 뒤 병합 비율: Human Check 런 중 이후 PR 상태가 병합됨인 비율(Q54·Q69).
- 러너·트래커 프로젝트·에이전트별 보기(티켓 0002).

## 완료 조건

- 테스트 DB의 런으로 각 지표 값이 손으로 계산한 값과 같다는 테스트가 통과한다.
- 러너·트래커 프로젝트·에이전트별 합이 전체와 같다는 테스트가 통과한다.
