# web Run 상세 화면

## 목표

런 하나의 결과와 이유, 타임라인, PR·CI, 로그 꼬리를 본다.

## 범위

- 이 티켓은 `apps/web`의 Run 상세 라우트와 그 화면 메시지만 고친다.
- 에이전트 결과와 PR 상태 두 칸, 그로부터 계산한 요약 결과(core 요약 계산 함수, Q66), 다음 행동, 타임라인(할당·시작·입력 기다림(질문과 답, 권한 대기)·연결 끊김·다시 연결·취소 요청·종료, Q67·Q82), 완료 보고 본문, 대기 시간과 실행 시간(Q59), PR·CI 상태(worker가 DB에 쓴 값, 0017. CI 상태를 읽을 권한이 없으면 "CI 상태를 볼 수 없어요", Q79), 이후 PR 상태(Q54·Q69).
- Disconnected 런은 "연결 끊김"과 ssh가 실패하기 시작한 시각을 보인다. 에이전트 결과가 러너 연결 끊김이고 워크트리를 아직 지우지 않았으면 "사람이 지워야 함"을 보인다. 지우기 버튼은 두지 않는다(Q75).
- 질문과 답: 질문으로 Waiting for Input인 런은 질문 내용과 답하기 칸을 보이고, 답하면 DB에 답을 남긴다. 지난 질문과 답은 타임라인에 남긴다. 권한 대기인 런은 "러너 화면에서 허용해 주세요"를 안내하고 거절만 둔다(Q82.3·Q82.4).
- 취소: 끝나지 않은 런(Queued, Running, Waiting for Input, Disconnected)에 취소 행동을 둔다. 누르면 DB에 취소 요청을 남기고 worker가 처리한다(Q61·Q77·Q82.8). 처리되지 않은 요청이 있으면 "취소 중"을 보인다(Q82.21). 에이전트 결과가 운영자가 취소함이고 러너에 닿지 못한 채 끝나 워크트리를 아직 지우지 않았으면 "사람이 지워야 함"을 보인다.
- Queued 이유: Q78로 러너를 비운 런은 "러너에서 프로젝트가 빠져 다시 고르는 중"을 보인다(Q82.13).
- 로그 꼬리: 화면을 열면 DB에 로그 꼬리 요청을 남기고, worker가 쓴 결과를 읽어 보인다. web은 ssh를 쓰지 않는다(Q61). Ended 런은 저장한 마지막 200줄을 보인다(Q46).
- 오른쪽에 런 속성과 같은 티켓의 다른 런(시안 B).

## 완료 조건

- core가 가진 에이전트 결과 전부(0037 뒤에는 스펙 4.2의 아홉)와 PR 상태 넷이 각각 맞는 문구로, 요약 결과(Canceled 포함)가 요약 계산 표대로 보인다는 테스트가 통과한다.
- Disconnected 런과 워크트리를 지우지 않은 러너 연결 끊김 런이 각각 "연결 끊김", "사람이 지워야 함"으로 보인다는 테스트가 통과한다.
- 화면을 열면 로그 꼬리 요청이 DB에 하나 생기고, DB에 결과를 넣으면 화면에 보인다는 테스트가 통과한다.
- Ended가 아닌 런에서만 취소 행동이 보이고, 누르면 취소 요청이 DB에 하나 생기며 "취소 중"이 보인다는 테스트가 통과한다.
- 질문으로 기다리는 런에서 답하면 DB에 답이 하나 생기고, 권한 대기 런에는 허용 행동이 없다는 테스트가 통과한다.
- CI 상태가 "볼 수 없음"인 런에서 "CI 상태를 볼 수 없어요"가 보이고 요약 결과는 그대로라는 테스트가 통과한다.
- web 코드에 ssh 호출이 없다.
