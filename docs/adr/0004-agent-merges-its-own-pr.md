# 병합은 에이전트가 직접 한다

런의 에이전트는 티켓을 수행한 뒤 PR을 열고, 사람의 확인이 필요 없으며 CI가 통과하면 그 PR을 머지 커밋으로 직접 병합한다. 오케스트레이터는 병합 정책을 갖지 않고, 런이 끝났을 때의 PR 상태로 결과만 판정한다(병합됨 → Merged, 열림 → Human Check, PR 없음 또는 병합 없이 닫힘 → Failed). 에이전트에게는 티켓만 지시로 주고, 병합 판단 기준은 각 프로젝트의 에이전트 설정(AGENTS.md, 스킬)에 둔다.

## Consequences

에이전트가 CI를 기다리는 동안 워크트리와 러너 capacity를 계속 차지한다. CI가 실패해 에이전트가 고치지 못하고 끝나면 PR이 열린 채 남으므로 Human Check로 분류된다.

병합 없이 닫힌 PR은 Failed로 판정한다(사유: PR이 닫힘). 에이전트가 스스로 PR을 포기한 것이라 사람이 확인할 대상이 아니라 실패에 가깝다.

런은 에이전트 프로세스가 끝나면 끝나고, 그때 위 규칙으로 판정한다. 최대 실행 시간(기본 2시간, Workspace별 설정)을 넘기면 오케스트레이터가 에이전트를 멈추고 PR 상태와 상관없이 Failed로 판정한다(사유: 시간 초과). 시간 초과로 멈춘 런이 PR을 열어 두었으면 결과는 Failed(시간 초과) 그대로지만, 그 PR과 워크트리는 Human Check처럼 PR이 병합되거나 닫힐 때까지 남긴다.

Failed 사유는 다섯이다. PR 없음(에이전트가 종료 코드 0으로 끝났고 PR이 없음), 에이전트 오류(에이전트가 0이 아닌 종료 코드로 끝났고 PR이 없음), 러너 연결 끊김(런 중 ssh가 5분 동안 계속 실패하거나 워크트리가 사라짐), PR이 닫힘, 시간 초과다.

Human Check 런의 결과는 런이 끝날 때 정한 그대로 두고, 그 뒤 PR이 병합되거나 닫히면 그 PR 상태를 런에 따로 기록한다.
