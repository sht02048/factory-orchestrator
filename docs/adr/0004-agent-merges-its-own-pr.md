# 병합은 에이전트가 직접 한다

런의 에이전트는 티켓을 수행한 뒤 PR을 열고, 사람의 확인이 필요 없으며 CI가 통과하면 그 PR을 머지 커밋으로 직접 병합한다. 오케스트레이터는 병합 정책을 갖지 않고, 런이 끝났을 때 **에이전트 결과**와 **PR 상태** 두 축을 따로 기록한다. 요약 결과(에이전트가 스스로 끝났으면 병합됨 → Merged, 열림 → Human Check, PR 없음 또는 병합 없이 닫힘 → Failed, 그 밖의 에이전트 결과는 PR과 상관없이 Failed)는 손댈 일 목록과 통계를 위해 두 축에서 계산만 한다. 에이전트에게는 티켓만 지시로 주고, 병합 판단 기준은 각 프로젝트의 에이전트 설정(AGENTS.md, 스킬)에 둔다.

## Consequences

에이전트가 CI를 기다리는 동안 워크트리와 러너 capacity를 계속 차지한다. CI가 실패해 에이전트가 고치지 못하고 끝나면 PR이 열린 채 남으므로 Human Check로 분류된다.

병합 없이 닫힌 PR은 요약 결과가 Failed다. 에이전트가 스스로 PR을 포기한 것이라 사람이 확인할 대상이 아니라 실패에 가깝다.

두 축은 따로 기록하고 화면에도 두 칸을 나란히 보인다. 에이전트 결과는 정상 종료(종료 코드 0), 오류 종료(0이 아님), 시간 초과, 입력 기다리다 멈춤, 러너 연결 끊김, 워크트리 없음, 운영자가 취소함 일곱이고, PR 상태는 런이 끝난 때의 없음, 열림, 병합됨, 닫힘 넷이다. 종료 코드는 요약 결과를 바꾸지 않는다. 오류 종료에 PR이 열려 있으면 요약은 Human Check이지만 두 칸에 함께 보여 그 조합이 숨지 않는다. 이전의 단일 결과와 Failed 사유는 저장하지 않고, Failed가 된 까닭은 두 축으로 말한다. 요약 계산 표는 [1단계 스펙](../spec/0001-phase-1.md) 4.2에 있고, 이전 판정 표와 최대한 같은 요약 결과를 낸다. 다른 곳은 아래 연결 끊김 하나다. 이전에는 ssh가 5분 실패하면 바로 Failed였지만, 이제는 다시 닿은 뒤 Merged나 Human Check로 끝날 수 있다.

런은 에이전트 프로세스가 끝나면 끝난다. 최대 실행 시간(기본 2시간, Workspace별 설정)을 넘기면 오케스트레이터가 에이전트를 멈추고, PR 상태와 상관없이 요약 결과는 Failed다(에이전트 결과: 시간 초과, Waiting for Input 중이었으면 입력 기다리다 멈춤). 이렇게 멈춘 런이 PR을 열어 두었으면 그 PR과 워크트리는 Human Check처럼 PR이 병합되거나 닫힐 때까지 남긴다.

런 중 러너에 ssh가 5분 동안 계속 닿지 않으면 런을 끝내지 않고 Disconnected(연결 끊김) 상태로 두고 손댈 일에 올린다. 워크트리는 건드리지 않는다. 다시 닿으면 실제 상태를 확인해, 에이전트가 돌고 있으면 Running으로(입력을 기다리고 있으면 Waiting for Input으로) 돌아가고, 이미 끝났으면 보통 런처럼 두 축을 기록하고, 워크트리가 사라졌으면 에이전트 결과 "워크트리 없음"으로 끝낸다. 최대 실행 시간이 지날 때까지 돌아오지 않으면 에이전트 결과 "러너 연결 끊김"으로 끝내고, 그 워크트리는 러너가 돌아온 뒤 사람이 정한다. 오케스트레이터가 자동으로 지우지 않는다. 1단계에는 지우기 버튼이 없어 사람이 러너에서 직접 지우고, worker는 워크트리가 사라진 것을 보면 지운 시각을 기록한다. 러너 하나가 잠깐 끊긴 것으로 아직 돌고 있을지 모르는 런을 실패로 단정하지 않기 위해서다.

운영자는 Queued와 Running 런을 취소할 수 있다. Queued 런은 바로 끝내고, Running 런은 오케스트레이터가 에이전트를 멈춘 뒤 끝낸다. 에이전트 결과는 "운영자가 취소함"이고 요약 결과는 PR 상태와 상관없이 Failed다. 워크트리는 PR이 열려 있으면 Human Check처럼 PR이 병합되거나 닫힐 때까지 남기고, 그 밖에는 지운다(Q77).

두 축은 런이 끝날 때 정한 그대로 둔다. 그 뒤 Human Check 런의 PR이 사람 손으로 병합되거나 닫히면 그 PR 상태를 이후 PR 상태로 런에 따로 기록한다.
