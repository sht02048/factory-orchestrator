# 병합은 에이전트가 직접 한다

런의 에이전트는 티켓을 수행한 뒤 PR을 열고, 사람의 확인이 필요 없으며 CI가 통과하면 그 PR을 머지 커밋으로 직접 병합한다. 오케스트레이터는 병합 정책을 갖지 않고, 런이 끝났을 때 **에이전트 결과**와 **PR 상태** 두 축을 따로 기록한다. 요약 결과(에이전트가 완료 보고를 보냈으면 병합됨 → Merged, 열림 → Human Check, PR 없음 또는 병합 없이 닫힘 → Failed, 운영자가 취소함은 PR과 상관없이 Canceled, 그 밖의 에이전트 결과는 PR과 상관없이 Failed)는 손댈 일 목록과 통계를 위해 두 축에서 계산만 한다. 에이전트에게는 티켓만 지시로 주고, 병합 판단 기준은 각 프로젝트의 에이전트 설정(AGENTS.md, 스킬)에 둔다.

## Consequences

에이전트가 CI를 기다리는 동안 워크트리와 러너 capacity를 계속 차지한다. 요약 결과에는 CI가 필요 없으므로 CI 상태는 화면의 선택 표시이고, GitHub 토큰에 CI를 읽을 권한이 없으면 "CI 상태를 볼 수 없어요"로 보인다(Q79). CI가 실패해 에이전트가 고치지 못하고 끝나면 PR이 열린 채 남으므로 Human Check로 분류된다.

병합 없이 닫힌 PR은 요약 결과가 Failed다. 에이전트가 스스로 PR을 포기한 것이라 사람이 확인할 대상이 아니라 실패에 가깝다.

두 축은 따로 기록하고 화면에도 두 칸을 나란히 보인다. 에이전트 결과는 완료 보고(성공), 완료 보고(실패), 비정상 종료, 시간 초과, 입력 기다리다 멈춤, 러너 연결 끊김, 워크트리 없음, 운영자가 취소함, 시작할 수 없음 아홉이고, PR 상태는 런이 끝난 때의 없음, 열림, 병합됨, 닫힘 넷이다. 에이전트는 대화형으로 떠 종료 코드가 없으므로, 에이전트 결과는 종료 코드가 아니라 완료 보고의 outcome으로 정한다([ADR 0009](0009-run-via-orca-orchestration.md), 운영자 결정 Q82 개정). 이전의 정상 종료·오류 종료는 완료 보고(성공)·완료 보고(실패)로 바꿨다. outcome은 요약 결과를 바꾸지 않는다. 완료 보고(실패)에 PR이 열려 있으면 요약은 Human Check이지만 두 칸에 함께 보여 그 조합이 숨지 않는다. 이전의 단일 결과와 Failed 사유는 저장하지 않고, Failed가 된 까닭은 두 축으로 말한다. 요약 계산 표는 [1단계 스펙](../spec/0001-phase-1.md) 4.2에 있고, 이전 판정 표와 최대한 같은 요약 결과를 낸다. 다른 곳은 둘이다. 이전에는 ssh가 5분 실패하면 바로 Failed였지만, 이제는 다시 닿은 뒤 Merged나 Human Check로 끝날 수 있다. 또 운영자가 취소한 런은 이제 Failed가 아니라 Canceled다.

런은 에이전트가 완료 보고를 보내면 끝나고, 보고를 받으면 오케스트레이터가 에이전트를 닫는다. 보고 없이 에이전트가 사라지면(Orca의 `lost` 알림, 에이전트 터미널이 사라짐, 셸만 남고 에이전트가 사라짐) 비정상 종료로 끝나고, 요약 결과는 PR 상태와 상관없이 Failed이며 워크트리는 아래 시간 초과와 같이 다룬다. 최대 실행 시간(기본 2시간, Workspace별 설정)을 넘기면 오케스트레이터가 에이전트를 멈추고, PR 상태와 상관없이 요약 결과는 Failed다(에이전트 결과: 시간 초과, Waiting for Input 중이었으면 입력 기다리다 멈춤). 이렇게 멈춘 런이 PR을 열어 두었으면 그 PR과 워크트리는 Human Check처럼 PR이 병합되거나 닫힐 때까지 남긴다.

런 중 러너에 ssh가 5분 동안 계속 닿지 않으면 런을 끝내지 않고 Disconnected(연결 끊김) 상태로 두고 손댈 일에 올린다. 워크트리는 건드리지 않는다. 다시 닿으면 실제 상태를 확인해, 에이전트가 돌고 있으면 Running으로(입력을 기다리고 있으면 Waiting for Input으로) 돌아가고, 이미 끝났으면 보통 런처럼 두 축을 기록하고, 워크트리가 사라졌으면 에이전트 결과 "워크트리 없음"으로 끝낸다. 최대 실행 시간이 지날 때까지 돌아오지 않으면 에이전트 결과 "러너 연결 끊김"으로 끝내고, 그 워크트리는 러너가 돌아온 뒤 사람이 정한다. 오케스트레이터가 자동으로 지우지 않는다. 1단계에는 지우기 버튼이 없어 사람이 러너에서 직접 지우고, worker는 워크트리가 사라진 것을 보면 지운 시각을 기록한다. 러너 하나가 잠깐 끊긴 것으로 아직 돌고 있을지 모르는 런을 실패로 단정하지 않기 위해서다.

운영자는 끝나지 않은 런을 어떤 상태에서든(Queued, Running, Waiting for Input, Disconnected) 취소할 수 있다. Queued 런은 바로 끝내고 PR을 찾지 않아 PR 상태는 없음이다. 그 밖의 런은 오케스트레이터가 에이전트를 멈춘 뒤 끝낸다. 멈추기가 실패하면 "취소 중"으로 두고 다시 시도하고, 러너에 닿지 않으면 연결 끊김 규칙을 따르다 다시 닿거나 최대 실행 시간이 지나면 끝낸다. 에이전트 결과는 "운영자가 취소함"이고 요약 결과는 PR 상태와 상관없이 Canceled다. 운영자가 스스로 멈춘 런이라 실패로 세지 않고, 손댈 일에서 빼며 통계에서 따로 센다. 워크트리는 PR이 열려 있으면 Human Check처럼 PR이 병합되거나 닫힐 때까지 남기고, 그 밖에는 지운다(Q77). 러너에 닿지 못한 채 취소로 끝난 런의 워크트리는 러너 연결 끊김처럼 자동으로 지우지 않고 사람이 정한다. 이것을 가르려고 런에 "러너에 닿지 못한 채 끝남"을 함께 기록한다.

대기열 맨 앞의 런이 영영 시작할 수 없으면(예: Mapping 삭제) 대기열이 막히지 않게 에이전트 결과 "시작할 수 없음"으로 끝내고 손댈 일에 올린다. PR을 찾지 않아 PR 상태는 없음이고, 워크트리가 없으며, 요약 결과는 Failed다.

두 축은 런이 끝날 때 정한 그대로 둔다. 그 뒤 Human Check 런의 PR이 사람 손으로 병합되거나 닫히면 그 PR 상태를 이후 PR 상태로 런에 따로 기록한다.
