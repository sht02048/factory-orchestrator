# GitHub push 실패는 러너가 아니라 그 러너 쪽 프로젝트만 할당에서 뺀다

러너 확인은 러너의 Orca에 추가된 저장소마다 `git push --dry-run`을 해 본다. 지금까지는 저장소 하나라도 실패하면 러너 전체를 할당에서 뺐고(Q82.14) 온보딩 러너 단계도 넘어가지 못했다. 운영자는 쓰지 않는 저장소나 쓰기 권한이 없는 포크 하나 때문에 러너 전체가 멈추는 일을 겪었다(티켓 0096, 2026-11-19).

## 결정

- **러너를 할당에서 빼는 조건은 러너 전체 조건뿐이다.** ssh로 닿는지(Online), 확인 오류, 러너 전체에 걸린 확인 항목(`project`가 없고 `blocksAssignment`인 항목)이다. Orca 상시 서비스는 지금처럼 할당을 막지 않고 온보딩에서만 요구한다.
- **push 실패는 그 러너 쪽 프로젝트에만 건다.** 확인 항목에 `project`를 붙이고, 실패(`satisfied: false`)한 프로젝트는 그 러너의 막힌 프로젝트가 된다. 자동 할당, 수동 할당, 대기열 모두 그 프로젝트로 Mapping된 티켓의 런만 그 러너에 맡기지 않는다. 다른 프로젝트 티켓은 그대로 맡긴다. 확인하지 못함(`null`, 시간 초과나 ssh 실패)은 막지 않는다.
- **막힌 프로젝트는 저장한 확인 결과에서 읽는다.** `runners.prerequisites` JSON에 `project`와 실패 이유(`failure`: 인증 실패, 네트워크, 시간 초과, 기타와 가린 stderr 한 줄)를 더한다. 칸을 새로 만들지 않는다. Offline 러너의 막힌 프로젝트는 비운다(어차피 할당하지 않는다).
- **화면 이유는 기존 "할당 막힘"을 쓴다.** 막힌 프로젝트 때문에 러너를 비우거나 정하지 못한 런의 이유는 `assignment-blocked`다. 새 이유 값을 만들지 않았다.
- **온보딩 러너 단계는 러너 전체 조건이 통과하면 다음으로 간다.** push 실패와 확인할 저장소가 없음은 경고로 보인다.

## 고려한 대안

- **지금처럼 러너 전체를 뺀다.** 저장소가 많을수록 러너가 멈출 일이 늘고, 실패한 저장소와 상관없는 티켓까지 기다린다.
- **`runner_projects`에 push 상태 칸을 둔다.** 조회는 단순해지지만 마이그레이션이 필요하고, 확인 결과(JSON)와 같은 사실을 두 곳에 둔다.
- **막힌 프로젝트용 새 대기 이유를 만든다.** 더 정확하지만 Dashboard·Runs·Run 상세의 이유 문구를 함께 바꿔야 한다. 지금 문구("러너의 GitHub 인증이 깨져 기다리는 중")로 뜻이 통해 미뤘다.

## 결과

- 할당 규칙이 바뀐다. 이전 확인 결과(프로젝트 없이 `blocksAssignment`인 push 항목)는 다음 러너 확인(1분 안)에 새 모양으로 바뀐다. 그 사이에는 이전처럼 러너 전체가 막힌다.
- 수동 할당 대화상자는 러너 단위로만 막힌 러너를 끈다. 막힌 프로젝트의 티켓을 그 러너에 맡기려 하면 서버가 "러너가 새 할당을 막고 있어요"로 거절한다.
