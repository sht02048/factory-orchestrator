# 트래커·러너·코드 호스트는 종류로 갈아 끼운다

나중에 Linear 외 트래커, Orca 외 러너, GitHub 외 코드 호스트가 늘 수 있다(운영자 요구, 2026-11-17). 그래서 외부 서비스는 어댑터 뒤에 두고, 늘릴 때 core를 고치지 않게 한다.

- **core에는 특정 서비스의 개념과 필드 이름을 두지 않는다.** 외부 ID는 core가 형식을 해석하지 않는 불투명한 문자열이고, 어떤 종류(kind)의 ID인지는 그 ID가 속한 연결·러너의 종류로 안다. Linear 팀 상태, Orca `worktreeId`, GitHub `headRefName` 같은 것은 어댑터 안에만 있다.
- **Tracker·Runner·CodeHost 인터페이스는 종류로 구분한다.** 설정에 저장한 연결·러너가 자기 종류를 갖고, 오케스트레이터는 그 종류의 어댑터를 부른다.
- **어댑터 하나는 패키지 하나와 한 곳의 등록으로 더한다.** 새 어댑터를 더할 때 고치는 곳은 새 패키지와 종류 → 어댑터 등록 한 곳뿐이다.

1단계는 종류마다 구현을 하나씩만 둔다: `packages/tracker-linear`, `packages/runner-orca`, `packages/codehost-github`([1단계 스펙](../spec/0001-phase-1.md) 5절, Q56). 다른 종류의 지원은 1단계 범위 밖이다(스펙 2절).

## Consequences

종류가 하나뿐인 1단계에서도 core 타입에 Linear·Orca·GitHub의 개념과 필드 이름을 쓰지 않는다. 지금 한 종류만 있다고 core에 그 서비스의 모양을 넣으면, 종류를 더할 때 core와 그것을 부르는 코드를 모두 고쳐야 한다.

1단계에서 Orca 러너의 상태 확인은 러너의 GitHub 인증을 함께 본다(스펙 9절). 러너 종류가 코드 호스트 종류에 기대는 곳이라, GitHub 외 코드 호스트를 더할 때 이 확인을 다시 본다.
