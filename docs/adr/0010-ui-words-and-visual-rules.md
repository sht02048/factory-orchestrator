# UI 낱말과 시각 규칙

운영자가 구현된 화면이 딱딱하다고 해 pen.dev로 시안을 다시 만들었고, 시안 B(왼쪽 아이콘 레일 + 손댈 일 카드 + 오른쪽 실시간 흐름)를 골랐다. 시안과 지금 화면을 점검하니 규칙이 16가지 깨져 있었다. 같은 상태를 한국어와 영어로 섞어 부르고(Waiting for Input의 "입력 기다림"과 Human Check), 같은 것을 여러 이름으로 부르고, 상태 모양과 색이 화면마다 다르고, 주 버튼이 한 화면에 여럿이고, 시간 표기가 7종, 제목 규칙이 3종이고, 메뉴에 Settings·Workspace가 빠져 있었다. 운영자가 2026-11-18에 아래 규칙을 정했다(Q14~Q21).

## 낱말

1. **상태 이름은 GLOSSARY의 영어 용어 그대로 쓴다.** 런 상태 Queued·Running·Waiting for Input·Disconnected, 요약 결과 Merged·Human Check·Failed·Canceled, 러너 Online·Offline. 손댈 일 종류는 Question·Permission·Human Check·Failed·Disconnected·Runner Issue이고, Runner Issue의 세부 원인(GitHub 인증 깨짐, Offline 등)은 설명 문장으로 쓴다.
2. **설명 문장·버튼·안내는 한국어 해요체로 쓴다.** "손댈 일", "전체"처럼 상태가 아닌 개념 낱말도 한국어로 둔다. 에이전트 결과와 PR 상태의 값(완료 보고(성공), 병합됨 등)은 상태 이름이 아니라 런이 어떻게 끝났는지 설명하는 값이라 한국어 그대로 둔다.
3. **메뉴·화면 이름은 Home·Tickets·Runs·Runners·Stats·Settings다.** 온보딩 단계 이름은 Tracker·GitHub·Runner·Workspace·Mapping이다.

## 모양

4. **상태는 "점 + 이름" 알약 하나로만 보인다.** 모든 화면에서 같은 컴포넌트를 쓴다.
5. **색 하나에 뜻 하나다.**

   | 색   | 뜻             | 상태                                        |
   | ---- | -------------- | ------------------------------------------- |
   | 보라 | 사람이 답·허용 | Question, Permission, Waiting for Input     |
   | 노랑 | 사람이 확인    | Human Check                                 |
   | 빨강 | 문제           | Failed, Disconnected, Runner Issue, Offline |
   | 초록 | 진행·정상      | Running, Online                             |
   | 파랑 | 병합           | Merged                                      |
   | 회색 | 대기·멈춤      | Queued, Canceled                            |

6. **파란 주 버튼은 화면의 주 행동 하나에만 쓴다.** 질문 선택지는 모두 같은 보조 버튼 모양이고, 추천 선택지처럼 칠하지 않는다. 위험 행동(취소, 거절)은 빨간 글자 보조 버튼이다.
7. **시간 표기는 세 가지다.** 진행 중인 것은 경과("25분째"), 지난 일은 상대 시간("25분 전", 1분 안이면 "방금", 하루가 넘으면 날짜), 타임라인은 시각("10:45")이다. 비율은 띄우지 않고 "2/2"로 쓴다.
8. **화면 제목은 메뉴와 같은 화면 이름이고, 그 아래 한 줄 요약 문장을 둔다.**
9. **티켓은 어디서나 "회색 키 + 제목"으로 보인다**(ACME-1 결제 실패 재시도).
10. **둥글기는 카드 12px, 버튼·행·입력 8px, 알약 6px이다.** 영역은 선이 아니라 면(배경색)으로 나눈다.
11. **레일 메뉴는 맨 위에 Workspace 바꾸기, 맨 아래에 Settings를 둔다.** Runners 아이콘에 문제 개수 점을 단다.

## 이유

- **일관성.** 같은 상태가 화면마다 다른 이름·모양·색이면 운영자는 같은 것인지 매번 확인해야 한다. 상태 알약, 시간 표기, 제목 규칙을 하나로 두면 화면을 옮겨도 읽는 법이 같다.
- **상태 이름을 GLOSSARY와 하나로.** 화면에서만 한국어로 바꾸면("실행 중", "입력 기다림", "연결 끊김", "취소") 코드·문서·화면의 이름이 둘이 되고, Human Check처럼 영어로 남은 이름과 섞인다. 상태 이름은 GLOSSARY 용어가 곧 화면 낱말이 되게 한다. 설명 문장은 읽히는 것이 목적이라 한국어로 둔다.
- **색 의미 겹침 해소.** 지금은 상태 대부분이 무채색이라 Running과 Queued, Waiting for Input과 Queued가 모양으로 구별되지 않고, 주황(Human Check)과 빨강(Failed)이 가까워 둘을 헷갈린다. 사람이 해야 할 일의 종류(답·허용, 확인, 문제 해결)마다 색을 하나씩 주면 손댈 일 카드에서 무엇을 할지 색으로 먼저 안다.

## ADR 0007과의 관계

이 ADR은 [ADR 0007](0007-ui-list-detail-panel.md)을 **보완하고 일부를 대체한다.**

- **남는 것.** 목록 + 오른쪽 상세 패널은 Runs·Tickets에 남는다. 행을 고르면 패널에 요약이 보이고, 행을 열면(두 번 누르기, Enter) Run 상세로 간다. Settings의 이 Workspace·설치 전체 나누기도 그대로다.
- **바뀌는 화면.** Home은 목록 + 패널 대신 손댈 일 카드와 오른쪽 "지금 일어나는 일" 흐름이다. Run 상세는 패널이 아니라 전체 화면으로 열고, 질문 카드를 위에, 그 아래 타임라인과 정보·터미널 끝부분을 둔다. Runners는 러너 카드(capacity 막대, 해결 안내)로 보인다. 온보딩은 가운데 한 열이 아니라 왼쪽 단계 목록·가운데 입력·확인 결과로 나눈다(사이드바 없는 첫 진입 전용 화면, 모든 단계 필수, 확인이 성공해야 다음으로 가는 점은 그대로).
- **대체하는 규칙.** 0007의 "색은 손댈 일에만 쓴다"(Human Check 주황), "카드와 배지를 쓰지 않는다", "구역은 옅은 선과 여백으로 나눈다"는 이 ADR의 5·10번과 카드 화면이 대신한다. 행 안의 위계(제목이 가장 밝고 굵고 ID·러너·시간은 흐리게, 숫자는 tabular-nums)는 그대로다.

대체가 아닌 보완으로 둔 까닭: 훑고 고르는 화면(Runs·Tickets)에서는 페이지를 옮기지 않는 목록 + 패널이 여전히 맞고, 바뀌는 것은 "할 일을 먼저 보여 줄 화면"(Home)과 "한 런을 깊게 볼 화면"(Run 상세)이다.

## Consequences

- **"지금 일어나는 일" 흐름은 DB에 이미 있는 사건만으로 시작한다.** 런 상태 바뀜(`run_state_changes`), 질문(`run_questions`), 권한 대기(`run_permission_waits`), 런 끝·PR 같은 기록이다. 시안의 "커밋 n개" 같은 런 중간 진행은 러너에서 받아 오는 데이터가 없어 빼고 시작한다. 넣으려면 러너 어댑터가 무엇을 얼마나 자주 읽을지 따로 정해야 한다.
- **`packages/ui`의 규칙 문서(`DESIGN.md`)와 토큰 시험이 바뀐다.** 지금 문서는 "카드와 배지를 쓰지 않는다", "색은 손댈 일에만", 반경 `md 6`을 적고, `tokens.test.ts`는 채도 있는 색을 포인트·Human Check·Failed·Online에만 허락한다. 적용 티켓([0049](../tickets/0049-ui-redesign.md))이 토큰·컴포넌트와 함께 고친다. 그 전까지 이 ADR과 `DESIGN.md`가 다르면 이 ADR이 앞선다.
- **포인트 파랑은 둘에 쓰인다.** Merged 알약과 주 버튼·링크다. 하나는 상태 알약, 하나는 행동이라 모양으로 갈린다. 알약의 파랑이 주 버튼과 헷갈리면 0049에서 알약 쪽 톤을 따로 정한다.
- **메시지 파일 낱말을 바꾼다.** "실행 중", "입력 기다림", "연결 끊김", "취소", "인증 깨짐", "권한 대기", "홈" 같은 상태·화면 이름을 영어 용어로 바꾸고, 시간 표기는 함수 하나로 모은다. 적용은 0049에서 한다.

## Considered Options

- **상태 이름도 모두 한국어로**: 화면은 한 언어가 되지만 GLOSSARY·코드의 영어 용어와 이름이 둘이 되고, Human Check·Merged처럼 마땅한 한국어가 없는 이름에서 다시 섞인다. 기각했다.
- **ADR 0007을 통째로 대체**: Runs·Tickets의 목록 + 패널은 운영자가 바꾸자고 하지 않았고 여전히 맞는다. 바뀐 화면과 규칙만 대체했다.
- **색을 손댈 일에만 두는 지금 규칙 유지**: 상태끼리 모양이 같아 구별되지 않는다는 점검 결과가 이 ADR의 출발이라 기각했다.
