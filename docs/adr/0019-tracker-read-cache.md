# 웹 서버가 트래커 읽기를 짧게 담아 두고, 바뀐 것이 알려지면 지운다

Tickets 로더는 트래커 티켓 목록을, Settings 로더는 트래커 프로젝트·상태·라벨을 화면을 열 때마다 트래커에 물었다. 운영자는 서버와 다른 기기(데스크톱 앱, tailnet 너머)에서 쓰고, 트래커 왕복 0.5~1.5초가 화면 이동마다 쌓였다(티켓 [0117](../tickets/0117-navigation-performance.md) 후속, [0122](../tickets/0122-remote-navigation.md)). 빨라지는 대신 오래된 티켓 상태를 얼마나 보일 수 있는지 정해야 했다.

## 결정

- **웹 서버 프로세스가 트래커 읽기 네 가지(`listProjectTickets`, `listProjects`, `listLabels`, `listStates`)를 연결별로 메모리에 담아 둔다.** 쓰기(`setState`, `addComment`, `createLabel`)와 webhook 확인, 연결 확인은 담아 두지 않는다. 실패한 읽기도 담아 두지 않아 다음 읽기가 다시 묻는다. Settings 의 동작(라벨 만들기 등)은 담아 둔 값을 쓰지 않고 트래커를 직접 읽는다.
- **stale-while-revalidate.** 담은 지 30초(`TRACKER_READ_FRESH_MS`) 안이면 그대로 준다. 30초~5분(`TRACKER_READ_MAX_AGE_MS`)이면 담아 둔 값을 바로 주고 뒤에서 새로 읽는다. 5분이 지났으면 트래커를 기다린다. 같은 읽기가 겹치면 트래커는 한 번만 부른다.
- **바뀐 것이 알려지면 지운다.** DB 표 `tracker_read_generations`에 연결마다 세대 수를 두고, 바뀐 일이 있으면 올린다. 담아 둔 값은 읽기 시작 때의 세대를 기억하고, 세대가 다르면 쓰지 않고 트래커를 기다린다. 읽는 동안 세대가 오르면 그 결과는 다음 읽기에 쓰지 않는다. 세대를 올리는 곳:
  - 트래커 webhook 을 기록했을 때(웹)
  - worker 의 폴링 보정이 바뀐 티켓을 읽었을 때, 런 시작 때 티켓 상태를 바꿨을 때(worker)
  - Ganger 에서 할당했을 때, 바로 할당 라벨을 만들었을 때, Mapping 을 저장했을 때, 트래커 연결을 저장하거나 확인했을 때(웹)
  - Tickets 머리의 "트래커에서 다시 읽기", Settings·온보딩의 "Linear에서 다시 읽기"(모든 연결)
- 웹과 worker 는 다른 프로세스라 메모리를 함께 쓸 수 없다. DB 의 세대 수 한 줄을 읽는 값(SQLite 한 문장, 1ms 미만)으로 두 프로세스가 같은 신호를 본다.

## 오래된 상태를 보일 수 있는 최대 시간

- webhook 을 설정한 연결: 트래커에서 바뀐 뒤 webhook 이 도착하기까지(보통 몇 초). 도착하면 다음 화면 열기부터 새 값이다.
- webhook 이 없거나 놓쳤을 때: **최대 5분**. 30초가 지난 뒤 화면을 열면 지난 값을 보이고 뒤에서 새로 읽어, 그다음 열기부터 새 값이다. 5분이 지난 값은 보이지 않는다. 바로 할당 라벨이 붙은 티켓은 worker 폴링 보정(1분)이 읽으면 지운다.
- 운영자는 "트래커에서 다시 읽기"로 언제든 지울 수 있다.

## 고려한 대안

- **담아 두지 않는다(지금까지).** 원격에서 Tickets·Settings 를 열 때마다 트래커 왕복을 기다린다.
- **TTL 만 둔다.** 할당하거나 라벨을 만든 직후에도 지난 값을 보여 운영자가 방금 한 일이 반영되지 않은 것처럼 보인다.
- **worker 가 트래커를 주기적으로 읽어 DB 에 티켓을 저장한다.** 화면은 늘 DB 만 읽어 가장 빠르지만, 티켓 표·동기화·삭제 처리를 새로 설계해야 한다. 지금 문제(왕복 몇 번)에 비해 크다.

## 결과

- 마이그레이션이 `tracker_read_generations` 표를 더한다(연결이 지워지면 함께 지워진다). 표만 더하므로 이전 버전 앱은 이 표를 무시한다.
- 서버를 다시 띄우면 담아 둔 값은 사라지고 첫 읽기는 트래커를 기다린다.
- 웹 서버 메모리는 연결·트래커 프로젝트·쪽 수만큼만 쓴다(Tickets 는 프로젝트당 최대 4쪽).
