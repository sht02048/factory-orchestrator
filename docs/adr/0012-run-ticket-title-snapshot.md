# 런의 티켓 제목은 할당 때 읽은 값을 남기고, 러너에는 Offline이 된 시각을 둔다

ADR 0010 9번은 티켓을 어디서나 "회색 키 + 제목"으로 보이라고 한다. 그런데 런에는 티켓 키만 있어, Dashboard·Runs·Run 상세는 제목 자리에 키를 두었다(티켓 0060). 제목은 Tickets 화면만 트래커에서 그때그때 읽는다. 러너도 Online/Offline만 있고 Offline이 된 시각이 없어, Runners 행이 "Offline · {경과}째" 대신 닿지 않는다고만 보였다. 티켓 0064가 두 값을 저장한다.

## 결정

- **`runs.ticket_title`(비어 있을 수 있는 글).** 할당할 때 아는 제목을 저장한다. 폴링 보정 자동 할당은 트래커 목록에서 읽은 제목을, 수동 할당은 Tickets 화면이 트래커에서 읽은 제목을 넘긴다. webhook 자동 할당은 이벤트에 제목이 없어 비운 채 만들고, worker가 런을 시작하며 프롬프트를 만들려고 티켓을 읽을 때 한 번 채운다. 한 번 채운 제목은 바꾸지 않는다.
- **트래커에서 제목이 바뀌어도 갱신하지 않는다.** 런의 제목은 "이 런이 맡은 일"의 기록이다. 에이전트가 받은 프롬프트도 할당·시작 때의 제목으로 만든다. 지금 제목은 Tickets 화면이 트래커에서 읽어 보인다.
- **`runners.offline_since`(비어 있을 수 있는 시각).** 러너 확인 결과가 Offline이면 비어 있을 때만 그 확인 시각을 넣고, Online이면 지운다. 처음부터 Offline인 러너는 처음 Offline으로 확인한 시각이 남는다. 화면은 Offline 러너의 경과를 `지금 − offline_since`로 계산한다. worker가 메모리에만 두는 잠깐의 닿지 않음(시작 명령 실패 뒤 대기)은 저장하지 않는다.
- **이미 있는 행은 비운 채 둔다.** 마이그레이션은 칸만 더한다(트래커에 닿을 수 없어 제목을 채울 수 없다). 제목이 없는 런은 키를 제목 자리에 보이고, 시각이 없는 Offline 러너는 경과 없이 Offline만 보인다. 다음 러너 확인이 Offline이면 그 시각이 들어간다.

## 고려한 대안

- **webhook `ticket.updated`로 제목을 갱신한다.** 트래커 이벤트에 제목을 더하고(core `TrackerEvent`, 어댑터 파싱, `tracker_events` 칸) 같은 티켓의 런을 모두 고쳐야 한다. 런 기록이 나중에 바뀌어 에이전트가 받은 일과 화면의 제목이 어긋날 수 있다. 지금 제목이 필요한 곳(Tickets)은 이미 트래커에서 읽는다.
- **화면이 열릴 때마다 트래커에서 제목을 읽는다.** Dashboard·Runs가 트래커 응답과 속도 제한에 묶이고, 트래커가 안 될 때 화면이 비게 된다(ADR 0001은 트래커를 일감의 원천으로 두지만 화면의 실시간 의존은 Tickets로 한정했다).
- **Offline 경과를 `checked_at`에서 계산한다.** `checked_at`은 확인할 때마다 바뀌어 "마지막 확인 뒤 경과"가 된다. Offline이 이어진 시간이 아니다.

## 결과

- 저장 형식이 바뀌는 one-way 변경이다. 칸을 지우려면 테이블을 다시 만드는 마이그레이션이 필요하다.
- 할당 경로가 셋(수동, webhook, 폴링)이고 webhook 경로만 시작 전까지 제목이 비어 있다. 그동안 화면은 키만 보인다.
